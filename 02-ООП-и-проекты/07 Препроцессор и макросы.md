# Препроцессор и макросы

> [!abstract] О чём заметка
> Препроцессор (preprocessor) — программа, которая обрабатывает текст исходных файлов **до** компиляции: подставляет файлы, заменяет идентификаторы, вырезает ненужные куски кода. Он работает с директивами, которые начинаются с `#`. Разберём все основные директивы, макросы с параметрами, их опасности и предопределённые константы.

## Где препроцессор в процессе сборки

Сборка программы — это конвейер:

```text
файлы с кодом      препроцессор      обработанные      компилятор      объектные      компоновщик    исполняемый файл
(.h и .cpp)   -->  (директивы #)  --> файлы кода   --> (в машинный --> файлы (.o) --> (линкер)  --> или библиотека
                                                         код)
```

Препроцессор — чисто **текстовый** инструмент: он ничего не знает о типах, функциях и синтаксисе C++. Он находит строки, начинающиеся с `#`, выполняет их и передаёт результат компилятору. Подробнее о следующих стадиях — в [[01 Компиляция и линковка]].

Результат работы препроцессора можно посмотреть: `g++ -E file.cpp` выводит код после обработки (флаг `-P` убирает служебные строки).

Список директив: `#define`, `#undef`, `#if`, `#elif`, `#else`, `#endif`, `#ifdef`, `#ifndef`, `#error`, `#include`, `#line`, `#pragma`, а также специфичные для Microsoft `#import` и `#using`.

## Директива #include

Уже знакомая директива: **препроцессор копирует содержимое указанного файла на место директивы** как есть. Используется для подключения заголовочных файлов, подробнее — в [[08 Многофайловые проекты и библиотеки]].

## Директива #define: символьные константы

`#define` создаёт **макрос (macro)** — ассоциацию между идентификатором и произвольной строкой (строка может быть пустой). Два варианта синтаксиса:

```text
#define <идентификатор> [<строка>]                       // символьная константа
#define <идентификатор>(<параметры>) [<строка>]          // макрос с параметрами
```

Начиная с этой строки, препроцессор заменяет каждое встреченное `<идентификатор>` на `<строку>`; если строка пустая, идентификатор просто исчезает. По традиции имена макросов пишут **ЗАГЛАВНЫМИ_БУКВАМИ**.

Применяют `#define` для трёх целей: константы, «пустые» флаги для проверки директивами условной компиляции и include guard (см. [[08 Многофайловые проекты и библиотеки]]).

```cpp
#include <iostream>
#define PI 3.14

int main()
{
    std::cout << "Число пи: " << PI << std::endl;        // Число пи: 3.14
    std::cout << "Число пи + 1: " << PI + 1 << std::endl; // Число пи + 1: 4.14
}
```

После препроцессора вместо `PI` в коде стоит `3.14`.

> [!warning] Подставляется ровно тот текст, что написан в `#define`
> Препроцессор не заменяет идентификаторы **внутри строковых литералов и комментариев**.
> ```cpp
> #define NAME John
> std::cout << "Привет, " << NAME;   // ОШИБКА: после замены получится  << John;  (нет такой переменной)
> ```
> Правильно — включить кавычки в само определение:
> ```cpp
> #define NAME "John"
> std::cout << "Привет, " << NAME << std::endl;   // Привет, John
> std::cout << "Привет, " << "NAME" << std::endl; // Привет, NAME  (строка в кавычках не заменяется)
> ```

> [!tip] Вместо констант-макросов в C++ лучше `const`/`constexpr`
> `constexpr double PI = 3.14;` имеет тип, область видимости (см. [[10 Область видимости и пространства имён]]) и понятен отладчику, а `#define` — просто текст.

## Директива #undef

`#undef <идентификатор>` заставляет препроцессор «забыть» ранее определённый макрос. Если идентификатор не был определён, ошибки нет.

```cpp
#define PI 3.14
std::cout << PI;      // 3.14
#undef PI
std::cout << PI;      // ОШИБКА компиляции: PI не объявлен
```

## Условная компиляция: #if, #elif, #else, #endif

Позволяет **включать или вырезать куски кода** ещё до компиляции. Синтаксис:

```text
#if <константное выражение 1>
    ...
#elif <константное выражение 2>      // сколько угодно #elif
    ...
#else                                // не более одного #else
    ...
#endif
```

Если выражение ненулевое — оно истинно и текст до следующей ветки остаётся; иначе вырезается и вообще не попадает в компилятор. `#elif` и `#else` — аналоги `else if` и `else`; они допустимы только между `#if` и `#endif`.

Требования к выражению: целочисленный тип, только целочисленные константы, символьные константы и оператор `defined`; **нельзя** `sizeof` и приведение типов.

### Оператор defined

`defined(ИМЯ)` или `defined ИМЯ` даёт истину, если макрос определён через `#define`. Результат можно инвертировать: `!defined(ИМЯ)`.

```cpp
#include <iostream>
#define PI 3.14      // E не определён

int main()
{
#if defined PI
    std::cout << "Мы знаем число пи: " << PI << std::endl;   // эта ветка останется
#endif
#if defined E
    std::cout << "Мы знаем число е: " << E << std::endl;     // будет вырезана
#endif
}
// Вывод: Мы знаем число пи: 3.14
```

Пример с `#elif`/`#else`:

```cpp
#define PI 3
#if PI == 3
    std::cout << "Сегодня пи равно 3" << std::endl;
#elif PI == 4
    std::cout << "Сегодня пи равно 4" << std::endl;
#else
    std::cout << "Мы не знаем пи" << std::endl;
#endif
// Вывод: Сегодня пи равно 3
```

### #ifdef и #ifndef

Сокращения: `#ifdef X` ≡ `#if defined X`, `#ifndef X` ≡ `#if !defined X`. Они тоже закрываются `#endif`. Классический пример `#ifndef` — include guard:

```cpp
#ifndef MY_HEADER_FILE
#define MY_HEADER_FILE
class MyClass { public: int method(); };
#endif
```

Типичное практическое применение условной компиляции — отладочный вывод и разные платформы. Макрос можно определить не в коде, а в командной строке компилятора:

```cpp
#include <iostream>
int main()
{
#ifdef DEBUG
    std::cout << "отладочный режим\n";
#endif
    std::cout << "работаем\n";
}
```

```bash
g++ -std=c++17 main.cpp -o app            # выведет только «работаем»
g++ -std=c++17 -DDEBUG main.cpp -o app    # -DDEBUG равносилен #define DEBUG; выведет обе строки
```

## Директива #error

`#error <сообщение>` останавливает компиляцию и выводит сообщение. Её цель — привлечь внимание разработчика к нарушению ограничения, обычно проверяют, что важный макрос определён. В сообщении макросы не подставляются.

```cpp
#ifndef MY_IMPORTANT_MACRO
#error Important macro required
#endif
```

Сборка без `-DMY_IMPORTANT_MACRO` закончится ошибкой `#error Important macro required`.

## Директива #line

`#line <номер> ["<имя файла>"]` меняет то, что вернут `__LINE__` и `__FILE__` дальше по тексту (удобно для кодогенераторов, чтобы сообщения ссылались на исходный файл).

```cpp
#include <iostream>
int main()
{
    std::cout << __LINE__ << " " << __FILE__ << "\n";   // 4 main.cpp
#line 20
    std::cout << __LINE__ << " " << __FILE__ << "\n";   // 20 main.cpp
#line 30 "hello.cpp"
    std::cout << __LINE__ << " " << __FILE__ << "\n";   // 30 hello.cpp
}
```

## Директивы #pragma, #import, #using

- `#pragma` — многофункциональная директива, поведение которой зависит от компилятора; конкретная команда задаётся строкой после неё. Основная для нас — `#pragma once` (защита от двойного подключения, см. [[08 Многофайловые проекты и библиотеки]]).
- `#import` (импорт информации из библиотеки типов) и `#using` (импорт метаданных) — специфические директивы Microsoft, в курсе подробно не разбираются.

## Макросы с параметрами

Если после имени в `#define` стоят скобки с параметрами, получается **макрос-«функция»**. Но это только **текстовая подстановка**: у параметров нет типов, никаких вызовов и проверок нет.

```cpp
#define MAX(a, b) a >= b ? a : b
int max = MAX(num1, num2);   // -> int max = num1 >= num2 ? num1 : num2;   работает
```

Но в другом контексте та же запись ломается:

```cpp
std::cout << "Максимум: " << MAX(num1, num2);
// -> std::cout << "Максимум: " << num1 >= num2 ? num1 : num2;   ОШИБКА
```

Из-за приоритета операторов выражение разбирается как `(cout << "..." << num1) >= num2 ? ...`. Правило: **заключайте в скобки каждый параметр в теле макроса и весь макрос целиком**:

```cpp
#define MAX(a, b) ((a) >= (b) ? (a) : (b))
```

Вторая классическая беда — параметры подставляются столько раз, сколько встречаются в теле:

```cpp
int num1 = 5, num2 = 10;
MAX(++num1, ++num2);
// -> ((++num1) >= (++num2) ? (++num1) : (++num2))
```

Инкремент выполнится дважды для победившего аргумента, и в слайдах результат — `12` вместо ожидаемых `11`.

> [!warning] Побочные эффекты в аргументах макроса
> Помимо двойного вычисления, такой код ещё и **неопределённое поведение**: в одном выражении `num2` изменяется несколько раз без упорядочивания (g++ предупреждает `-Wsequence-point`). Поэтому результат «12» нельзя считать гарантированным. Вывод: **не передавайте в макросы выражения с побочными эффектами и вызовы функций**.

Ещё пример со скобками:

```cpp
#define SQR_BAD(x) x * x
#define SQR(x)     ((x) * (x))
SQR_BAD(1 + 2)   // -> 1 + 2 * 1 + 2 = 5
SQR(1 + 2)       // -> ((1 + 2) * (1 + 2)) = 9
```

### Многострочные макросы

Макрос может состоять из нескольких операторов. Для переноса строки в конце ставят обратный слэш `\`:

```cpp
#define SWAP(type, a, b) \
    type tmp = (a);      \
    (a) = (b);           \
    (b) = tmp;
```

Но такой макрос в слайдах «голый»: он объявляет переменную `tmp` прямо в месте вызова, поэтому второй `SWAP` в том же блоке даст ошибку повторного объявления, а в `if (x) SWAP(...)` без фигурных скобок в ветку попадёт только первая строка. Правило безопасности — **многострочный макрос должен иметь свою область видимости**. Стандартный приём — обернуть тело в `do { ... } while (0)`:

```cpp
#include <iostream>
#define SWAP(type, a, b) do { type tmp = (a); (a) = (b); (b) = tmp; } while (0)

int main()
{
    int x = 5, y = 10;
    SWAP(int, x, y);
    SWAP(int, x, y);                       // второй вызов безопасен: tmp живёт только внутри do-while
    std::cout << x << " " << y << "\n";    // Вывод: 5 10
}
```

### Операторы # и ## (дополнение)

В теле макроса `#x` превращает аргумент в строковый литерал, а `a##b` склеивает два токена в один:

```cpp
#define STR(x) #x
#define CONCAT(a, b) a##b
std::cout << STR(hello world);   // hello world
int xy = 7;
std::cout << CONCAT(x, y);       // 7
```

### Итог о макросах

**В C++ использование макросов не рекомендуется.** В языке C альтернатив не было, а в C++ те же задачи решают безопасные средства: `const`/`constexpr` вместо констант, `inline`-функции и шаблоны (см. [[05 Шаблоны и функторы]]) вместо макросов-функций, `enum` вместо наборов констант. Если макросы всё же нужны, соблюдайте правила:

1. не передавайте в параметры выражения и вызовы функций;
2. заключайте в скобки все параметры и сам макрос;
3. многострочные макросы изолируйте областью видимости (`do { } while (0)`).

## Предопределённые символьные константы

Компилятор сам определяет ряд макросов. Почти все они имеют форму `__ИМЯ__` (двойное подчёркивание с обеих сторон) — **не называйте так свои константы**. Часть констант зависит от компилятора, но перечисленные ниже — стандартные:

| Константа | Что содержит |
|---|---|
| `__func__` | имя функции, внутри которой использована (на самом деле это не макрос, а скрытая переменная функции, но используется так же) |
| `__cplusplus` | определена, если файл компилируется компилятором C++ (значение — номер стандарта, например `201703L` для C++17) |
| `__DATE__` | дата компиляции, строка `"Mm dd yyyy"` |
| `__FILE__` | имя текущего файла |
| `__LINE__` | номер текущей строки |
| `__STDC__` | равна 1, если файл компилирует компилятор C; иначе не определена (есть «сёстры» `__STDC_…`) |
| `__TIME__` | время компиляции, строка `"hh:mm:ss"` |

Хороший пример их применения — макрос логирования, который сам подставляет место вызова:

```cpp
#include <iostream>
#define LOG(msg) std::cout << __FILE__ << ":" << __LINE__ << " [" << __func__ << "] " << (msg) << std::endl

int main()
{
    LOG("запуск");   // Вывод: main.cpp:5 [main] запуск
}
```

```cpp
#if defined(__cplusplus) && __cplusplus >= 201703L
    // код, требующий C++17
#endif
```

## Частые ошибки

- Подстановка вместо значения-строки без кавычек (`#define NAME John`) — получаем несуществующий идентификатор.
- Макрос-функция без скобок вокруг параметров и всего тела — неверный порядок операций.
- `MAX(++a, f())` — двойное вычисление аргументов и неопределённое поведение.
- Точка с запятой в конце `#define PI 3.14;` — она станет частью подстановки и сломает выражения вроде `PI + 1`.
- Забытый `#endif`.
- Имя макроса совпадает с именем переменной или функции: препроцессор заменит и их (макросы не знают областей видимости).

## Кратко (шпаргалка)

- Препроцессор работает до компилятора, это замена текста; директивы начинаются с `#`.
- `#include` копирует файл; `#define NAME value` — подстановка; `#undef` — забыть.
- `#if/#elif/#else/#endif`, `#ifdef`, `#ifndef`, `defined` — условная компиляция; `-DNAME` задаёт макрос из командной строки.
- `#error` — остановить сборку с сообщением; `#line` — подменить `__LINE__`/`__FILE__`; `#pragma once` — защита заголовка.
- Макросы-функции: всё в скобки, без побочных эффектов в аргументах, многострочные — через `do { } while (0)`; в C++ предпочитайте `constexpr`, `inline`, шаблоны.
- Стандартные константы: `__func__`, `__cplusplus`, `__DATE__`, `__TIME__`, `__FILE__`, `__LINE__`, `__STDC__`.
