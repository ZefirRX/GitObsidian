# Многофайловые проекты и библиотеки

> [!abstract] О чём заметка
> Когда программа вырастает до сотен строк, её разносят по нескольким файлам: объявления лежат в заголовочных файлах (`.h`), реализации — в файлах исходного кода (`.cpp`). Разберём, зачем нужны заголовки, как работает `#include`, как защититься от двойного подключения и как вынести в отдельные файлы функцию и класс. Сами «библиотеки» (статические и динамические) — в [[09 Сборка и подключение библиотек]].

## Зачем делить программу на файлы

В большом файле трудно ориентироваться: нужно помнить, какие функции и классы созданы, и постоянно искать нужное место. Обычно в программе легко выделить части, решающие разные задачи, — их и разносят по файлам. Это упрощает разработку и поддержку, а ещё позволяет **переиспользовать** код.

В C++ используются два основных вида файлов:

| Файл | Расширение | Что содержит |
|---|---|---|
| Исходный (source file) | `.cpp` | основная часть кода: определения функций, методов; здесь же `main` |
| Заголовочный (header file) | `.h` (иногда `.hpp`) | объявления функций и переменных, определения классов без реализации методов |

> [!note] Единица трансляции
> Каждый `.cpp` компилируется **отдельно** в объектный файл (`.o`/`.obj`), а затем линковщик собирает объектные файлы в программу (см. [[01 Компиляция и линковка]]). Поэтому при компиляции одного `.cpp` компилятор видит только его текст — и ему нужно сообщить, что существуют функции из других файлов.

В Visual Studio файл добавляют так: правый клик по проекту в Обозревателе решений → «Добавить» → «Создать элемент» → «Файл C++ (.cpp)» или «Файл заголовка (.h)». «Папки» в Обозревателе решений — это лишь фильтры, а не каталоги файловой системы.

## Первая попытка: вынос функции

Допустим, функцию возведения в квадрат хотим вынести из основного файла:

```cpp
// math_power.cpp
int power_2(int x) { return x * x; }

// source.cpp
#include <iostream>
int main() { std::cout << power_2(5) << std::endl; }
```

Сборка не пройдёт: `power_2` не объявлена в `source.cpp`. Компилятор обрабатывает файл сверху вниз и должен знать имя до использования.

Можно написать в `source.cpp` **прототип** (объявление):

```cpp
int power_2(int x);   // объявление: тип возврата, имя, параметры; тела нет
int main() { std::cout << power_2(5) << std::endl; }   // 25
```

Это соберётся и заработает, но **так никто не делает**:

- высокая вероятность ошибки: чужие функции и классы придётся переписывать вручную со всеми типами аргументов и перегрузками;
- плохо масштабируется: переиспользование кода становится невозможным, ведь половина вашего кода — копии прототипов; непонятно, где они определены, и имена должны быть уникальны.

Общепринятое решение — заголовочные файлы.

## Заголовочные файлы

Заголовочный файл почти всегда идёт в паре с `.cpp` того же имени. В нём размещаются **объявления** функций и переменных и **определения классов без реализации методов**. Заголовок выступает **интерфейсом**: он сообщает, что доступно для внешнего использования, а реализация остаётся в `.cpp`. Подключают заголовок директивой `#include` (см. [[07 Препроцессор и макросы]]) — препроцессор копирует содержимое файла на место директивы.

```cpp
// math_power.h
#pragma once
int power_2(int x);              // объявление

// math_power.cpp
#include "math_power.h"          // в .cpp обычно подключают свой заголовок
int power_2(int x)               // определение
{
    return x * x;
}

// source.cpp
#include <iostream>
#include "math_power.h"
int main()
{
    std::cout << power_2(5) << std::endl;   // 25
}
```

Заголовок пишется один раз, и все желающие просто подключают его — ошибки переписывания и проблема масштабирования исчезают.

> [!tip] Почему в `.cpp` подключают свой заголовок
> Так компилятор проверит, что определение совпадает с объявлением (сигнатуры не разошлись), и порядок определений в `.cpp` перестаёт иметь значение.

### Два вида #include

| Синтаксис | Где ищет файл | Когда использовать |
|---|---|---|
| `#include <iostream>` | в специальных системных каталогах компилятора | стандартные и сторонние библиотеки |
| `#include "math_power.h"` | сначала в каталогах проекта (рядом с текущим файлом), затем как для `<>` | собственные заголовки |

> [!note] Почему всё так сложно
> Подобная схема существует по историческим причинам: когда создавался C++, компьютеры были слабыми, и часть работы по связыванию разнесённых по файлам кусков кода (которую современные языки делают сами) переложили на программиста.

## Проблема двойного подключения

Пусть `a.h` определяет структуру `foo`, `b.h` подключает `a.h`, а `source.cpp` подключает и `a.h`, и `b.h`. Через `b.h` текст `a.h` попадёт в `source.cpp` дважды — получится два определения `foo`:

```cpp
// a.h
struct foo { int field; };
// b.h
#include "a.h"
// source.cpp
#include "a.h"
#include "b.h"
int main() { }
```

Ошибка компиляции: **redefinition of 'struct foo'** (переопределение структуры). Такие «ромбы» подключений в реальных проектах возникают постоянно, поэтому каждый заголовок защищают одним из двух способов.

### Include guards («стражи подключения»)

Конструкция из `#ifndef`, `#define`, `#endif`:

```cpp
#ifndef MATH_POWER_H
#define MATH_POWER_H

int power_2(int x);

#endif
```

При первом подключении макрос `MATH_POWER_H` не определён — содержимое включается и макрос определяется; при повторном макрос уже есть, и всё между `#ifndef` и `#endif` вырезается. Строка-идентификатор должна быть **уникальной для проекта**, без пробелов и русских букв. Это старый, но самый переносимый механизм.

### #pragma once

Одна строка в начале файла:

```cpp
#pragma once
int power_2(int x);
```

Проще и не требует придумывать уникальные имена. Минус: теоретически его могут не поддерживать очень старые компиляторы (на практике поддерживают все основные). В курсе `#pragma once` считается **предпочтительнее include guards**. Рабочее правило: каждый `.h` начинается с `#pragma once` (или имеет guard).

> [!warning] Что нельзя класть в заголовок
> Определения обычных (не `inline`) функций и глобальных переменных. Заголовок копируется во **все** `.cpp`, которые его подключают, и линковщик увидит несколько определений: `multiple definition of 'power_2(int)'`. В заголовке — объявления, определения классов и `inline`/шаблонные функции (см. [[05 Шаблоны и функторы]]).

## Вынесение класса в отдельный файл

Классы — самостоятельные единицы, их логично выносить в пару `.h` + `.cpp`. Пусть есть класс `Calculator` с методом `power_2`. Наивная попытка:

```cpp
// calculator.h
#pragma once
class Calculator;            // только объявление класса

// calculator.cpp
#include "calculator.h"
class Calculator { int power_2(int x) { return x * x; } };   // определение здесь

// source.cpp
#include "calculator.h"
int main() { Calculator c; c.power_2(5); }   // ОШИБКА
```

Ошибка: **тип `Calculator` неполный** (incomplete type; в g++ — «aggregate has incomplete type and cannot be defined»). В `source.cpp` из заголовка известно лишь, что такой класс существует: компилятор не знает ни его размера (сколько памяти выделить под объект), ни методов, ни полей. Поэтому **в заголовке должно быть полное определение класса со списком всех членов**, а реализации методов можно вынести в `.cpp`.

### Внешнее определение членов класса

В `.cpp` метод определяют **вне класса**, указывая перед именем члена название класса и оператор области видимости `::`:

```cpp
class MyClass
{
public:
    int field;
    MyClass();          // объявление конструктора
    void method();      // объявление метода
};
MyClass::MyClass() { /* ... */ }        // определение конструктора
void MyClass::method() { /* ... */ }    // определение метода
```

Правильный вариант с калькулятором (методы должны быть `public`, иначе `source.cpp` их не вызовет; см. [[03 Абстракция и инкапсуляция]]):

```cpp
// calculator.h
#pragma once
class Calculator
{
public:
    int power_2(int x);
};

// calculator.cpp
#include "calculator.h"
int Calculator::power_2(int x) { return x * x; }

// source.cpp
#include <iostream>
#include "calculator.h"
int main()
{
    Calculator c;
    std::cout << c.power_2(5) << std::endl;   // 25
}
```

Подробнее о классах — [[02 Классы и объекты]].

## Полный рабочий пример и сборка вручную

Структура проекта:

```text
project/
├── a.h
├── b.h
├── math_power.h
├── math_power.cpp
├── calculator.h
├── calculator.cpp
└── main.cpp
```

Содержимое вспомогательных файлов (все заголовки защищены `#pragma once`):

```cpp
// a.h
#pragma once
struct foo { int field; };

// b.h
#pragma once
#include "a.h"

// math_power.h
#pragma once
int power_2(int x);

// math_power.cpp
#include "math_power.h"
int power_2(int x) { return x * x; }

// calculator.h
#pragma once
class Calculator
{
public:
    int power_2(int x);
};

// calculator.cpp
#include "calculator.h"
int Calculator::power_2(int x) { return x * x; }
```

Главный файл:

```cpp
// main.cpp
#include <iostream>
#include "math_power.h"
#include "calculator.h"
#include "a.h"
#include "b.h"          // b.h подключает a.h — благодаря #pragma once конфликта нет

int main()
{
    Calculator c;
    foo f{3};
    std::cout << power_2(5) << " " << c.power_2(6) << " " << f.field << std::endl;
}
// Вывод: 25 36 3
```

```bash
# каждый .cpp компилируется отдельно в объектный файл, затем линкуются вместе
g++ -std=c++17 -Wall -c math_power.cpp calculator.cpp main.cpp
g++ main.o math_power.o calculator.o -o app
./app
```

Заголовки в команде не указываются: их текст приходит в `.cpp` через `#include`. Менять в проекте нужно только те `.cpp`, которые затронуты правкой, остальные `.o` можно не пересобирать — отсюда ускорение сборки больших проектов.

## Частые ошибки

| Симптом | Причина |
|---|---|
| `'power_2' was not declared in this scope` | не подключён заголовок с объявлением |
| `undefined reference to 'power_2(int)'` (ошибка линковщика) | объявление есть, а `.cpp` с определением не попал в сборку |
| `multiple definition of ...` | функция/переменная определена в заголовке (без `inline`) или в двух `.cpp` |
| `redefinition of 'struct foo'` | нет `#pragma once`/include guard |
| `incomplete type` | в заголовке только `class X;`, а нужен полный класс |
| `#include <my.h>` не находит свой файл | для своих файлов используйте кавычки |

## Кратко (шпаргалка)

- Исходники `.cpp` — реализации; заголовки `.h` — объявления и интерфейс; пара с одним именем.
- `#include` копирует файл на своё место: `<...>` — системные, `"..."` — свои.
- Каждый заголовок защищайте: `#pragma once` (предпочтительно) или `#ifndef/#define/#endif`.
- В заголовке — полное определение класса; методы реализуются в `.cpp` как `Класс::метод`.
- Не определяйте обычные функции и глобальные переменные в `.h`.
- Каждый `.cpp` компилируется отдельно, затем линковщик собирает `.o` в программу.

## Задачи для практики

1. Вынесите функцию `power_2` в пару `math_power.h/.cpp` и подключите из `main.cpp` (решение — раздел «Заголовочные файлы» выше).
2. Создайте `a.h` со структурой, `b.h`, подключающий `a.h`, и `main.cpp`, подключающий оба; убедитесь, что без защиты сборка падает, а с `#pragma once` проходит.
3. Вынесите класс с несколькими методами (конструктор, геттер) в `.h/.cpp`, определив методы через `Класс::метод`.
