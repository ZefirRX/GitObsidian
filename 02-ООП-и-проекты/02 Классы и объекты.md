# Классы и объекты

> [!abstract] О чём заметка
> Класс (class) — основа объектно-ориентированного программирования (ООП): пользовательский тип, объединяющий данные и операции над ними. Заметка разбирает члены класса (поля, методы, конструкторы), ключевое слово `this`, модификаторы доступа `public`/`protected`/`private`, геттеры и сеттеры и единственное отличие класса от структуры.

## Что такое класс и объект

В общем смысле **класс — это сущность, объединяющая данные и операции над этими данными**. В C++ это пользовательский тип данных, в котором описаны данные и поведение (работа с ними). Он очень похож на структуру из [[01 Структуры и перечисления]]; единственное отличие мы рассмотрим ниже.

Объявление класса — это своего рода «схема» (чертёж). Конкретные экземпляры, построенные по этой схеме, называются **экземплярами класса, или объектами** (object). Класс объявляется один раз, а объектов может быть сколько угодно.

> [!example] Аналогия
> Чертёж дома — это класс, а построенные по нему дома — объекты. Чертёж один, домов может быть много, и у каждого свои жильцы (значения полей). Идея «программа как набор общающихся объектов» подробнее разобрана в [[03 Абстракция и инкапсуляция]].

```cpp
class <название класса>
{
public:
    <члены класса>
};
```

**Члены класса** — это всё, из чего класс состоит и что он умеет делать. Слово `public:` в начале нужно, чтобы к членам можно было обращаться из внешнего кода (подробнее — в разделе про модификаторы доступа).

```cpp
class Person
{
public:
    std::string first_name;
    std::string last_name;
    int age;
};
```

## Члены класса

### Поля

**Поля (fields)** — это «переменные» внутри одного объекта. У каждого поля есть тип и имя. Поля хранят данные, специфичные для конкретного экземпляра; потом их используют внешний код и методы самого класса. У `Person` три поля: две строки и `int`.

### Методы

> [!note] Определение
> **Метод (method)** — функция, «принадлежащая» объекту. Вызывается через точку: `объект.метод()`.

Синтаксис такой же, как у обычной функции, но объявляется внутри класса. Метод имеет прямой доступ к полям своего объекта.

```cpp
#include <iostream>
#include <string>

class Person
{
public:
    std::string first_name;
    std::string last_name;
    int age;

    void print_person()
    {
        std::cout << "Имя: " << first_name << " Фамилия: " << last_name
                  << " Возраст: " << age << std::endl;
    }
};

int main()
{
    Person person;
    person.first_name = "Иван";
    person.last_name = "Иванов";
    person.age = 40;
    person.print_person();  // Вывод: Имя: Иван Фамилия: Иванов Возраст: 40
}
```

Объект можно создать и в динамической памяти. Тогда у него обращаются к членам через стрелку (как со структурой, см. [[01 Структуры и перечисления]]), а удалять его нужно самим:

```cpp
Person* p = new Person("Анна", "Ли", 25);
p->print_person();   // Вывод: Имя: Анна Фамилия: Ли Возраст: 25
delete p;            // не забываем освободить память
```

> [!warning] Неинициализированные поля
> Если вызвать `print_person()` у только что созданного `Person person;`, имя и фамилия будут пустыми, а `age` — случайным числом (на слайдах это было `-858993460`). Поля встроенных типов сами не обнуляются. Именно для этого придуманы конструкторы.

Методы мы уже использовали: у `std::ifstream`/`ofstream` — `is_open`, `close` (см. [[11 Работа с файлами]]), у `std::string` — `length`, `find` (см. [[06 Строки]]).

### Ключевое слово `this`

Внутри метода доступен `this` — **указатель на объект, у которого вызван метод**. Тип `this` — указатель на текущий класс, поэтому к членам обращаются через стрелку `->`. Обычно `this` не нужен, но он необходим, когда имя параметра совпадает с именем поля:

```cpp
class Person
{
public:
    int age = 30;

    void change_age_wrong(int age) { age = age; }       // присваивает параметру самому себе! поле не меняется
    void change_age(int age)       { this->age = age; } // верно: поле = параметр
};

int main()
{
    Person p;
    p.change_age_wrong(50);
    std::cout << p.age << "\n";  // Вывод: 30  (поле не изменилось)
    p.change_age(50);
    std::cout << p.age << "\n";  // Вывод: 50
}
```

Почему так: внутри метода имя `age` — это ближайшее объявление, то есть параметр. Поле он «затеняет» (shadowing), а `this->age` указывает на поле явно.

Ещё одно применение `this` — вернуть сам объект, чтобы вызовы можно было выстраивать в цепочку:

```cpp
Person& birthday() { ++age; return *this; }  // *this — сам объект, возвращаем ссылку

// p.birthday().birthday();  // два дня рождения подряд: возраст вырос на 2
```

### Конструкторы

Чтобы объект сразу создавался в корректном состоянии, а не «с мусором» в полях, используют конструкторы.

> [!note] Определение
> **Конструктор (constructor)** — специальный метод, который автоматически вызывается при создании объекта. В нём пишется код, который должен выполниться при создании экземпляра.

Правила:

- имя конструктора **совпадает с именем класса** — так его отличают от обычных методов;
- **возвращаемого значения нет**, и тип указывать нельзя (даже `void`);
- у класса всегда есть хотя бы один конструктор;
- конструкторов может быть несколько — они различаются числом и типами параметров (перегрузка);
- при создании объекта выбирается тот конструктор, который подходит под переданные аргументы.

```cpp
class Person
{
public:
    std::string first_name;
    std::string last_name;
    int age;

    // конструктор с параметрами
    Person(std::string first_name, std::string last_name, int age)
    {
        this->first_name = first_name;
        this->last_name = last_name;
        this->age = age;
    }
};
```

#### Конструктор по умолчанию

**Конструктор по умолчанию (default constructor)** — конструктор без параметров. Если программист **не написал ни одного** конструктора, компилятор сам сгенерирует пустой конструктор без параметров (поэтому наш первый класс без конструкторов работал). Но если вы написали **хотя бы один** конструктор, автоматический конструктор по умолчанию **не создаётся**.

Для конструкторов без параметров пустые скобки при создании объекта писать не нужно: `Person person;`.

```cpp
Person person;  // ОШИБКА, если в классе только конструктор с параметрами
// error: no matching function for call to 'Person::Person()'
```

Исправить это можно двумя способами:

1. **Передать нужные значения** при создании: `Person person("Пётр", "Петров", 30);`. Это самый правильный путь, если мы как раз и добивались того, чтобы нельзя было создать `Person` без заполненных полей.
2. **Добавить второй конструктор без параметров**, в котором полям придумываются значения по умолчанию.

Полный пример с обоими конструкторами:

```cpp
#include <iostream>
#include <string>

class Person
{
public:
    std::string first_name;
    std::string last_name;
    int age;

    Person(std::string first_name, std::string last_name, int age)
    {
        this->first_name = first_name;
        this->last_name = last_name;
        this->age = age;
    }

    Person()  // конструктор по умолчанию, написанный вручную
    {
        first_name = "Неизвестно";
        last_name = "Неизвестна";
        age = 18;
    }

    void print_person()
    {
        std::cout << "Имя: " << first_name << " Фамилия: " << last_name
                  << " Возраст: " << age << std::endl;
    }
};

int main()
{
    Person a("Пётр", "Петров", 30);
    Person b;
    a.print_person();  // Вывод: Имя: Пётр Фамилия: Петров Возраст: 30
    b.print_person();  // Вывод: Имя: Неизвестно Фамилия: Неизвестна Возраст: 18
}
```

Создавать объект можно и с фигурными скобками: `Person t{"Иван", "Сидоров", 41};` — выберется тот же конструктор с тремя параметрами.

> [!tip] Список инициализации
> В C++ поля принято инициализировать не в теле конструктора, а в **списке инициализации**: `Person(std::string f, std::string l, int a) : first_name(f), last_name(l), age(a) {}`. Это за пределами слайдов, но так делают в реальном коде: поля сразу получают значение, а не создаются пустыми и потом перезаписываются.

Заодно ответ на вопрос слайдов, как работал класс без единого написанного конструктора: конструктор у него всё-таки был — **неявный, сгенерированный компилятором**. Он ничего не делает с полями простых типов, поэтому `age` и содержал мусор.

Итого, мы рассмотрели три вида членов класса: **поля, методы, конструкторы**. Это не полный список, но самые нужные.

## Модификаторы доступа

**Модификатор доступа (access specifier)** определяет, откуда можно использовать помеченный им член. Их три: `public`, `protected`, `private`. Они применяются к членам класса (здесь) и при наследовании (см. [[05 Наследование и полиморфизм]]).

Модификатор записывается внутри класса с двоеточием и действует на все члены ниже, вплоть до следующего модификатора:

```cpp
class MyClass
{
public:
    // члены 1, 2 — публичные
private:
    // члены 3, 4 — приватные
public:
    // член 5 — снова публичный
};
```

- **`private`** — член доступен только коду внутри самого класса (методам и конструкторам).
- **`protected`** — доступен внутри класса и в его наследниках. Пока наследование не изучено, ведёт себя как `private`.
- **`public`** — доступен любому коду; это «интерфейс» класса для его пользователей.

| Откуда обращаемся | `private` | `protected` | `public` |
|---|---|---|---|
| Внутри класса | да | да | да |
| Внутри наследников | нет | да | да |
| Снаружи класса | нет | нет | да |

```cpp
class TestClass
{
private:
    int priv_field = 1;
    void priv_method() { std::cout << priv_field; }  // внутри класса можно
};

int main()
{
    TestClass test;
    // std::cout << test.priv_field;  // ошибка доступа
    // test.priv_method();            // ошибка доступа
}
```

### Геттеры и сеттеры

Поля обычно делают приватными (почему — см. [[03 Абстракция и инкапсуляция]]), а для доступа снаружи предоставляют методы: **геттер (getter)** читает значение, **сеттер (setter)** записывает и при необходимости проверяет его.

```cpp
#include <iostream>

class Account
{
private:
    int balance = 0;

public:
    int get_balance() const { return balance; }      // геттер (const: метод не меняет объект)
    void set_balance(int value)                       // сеттер с проверкой
    {
        if (value >= 0)
            balance = value;
    }
};

int main()
{
    Account acc;
    acc.set_balance(5);
    acc.set_balance(-3);                  // отвергнуто проверкой
    std::cout << acc.get_balance() << "\n";  // Вывод: 5
}
```

> [!warning] Не забывайте скобки у метода
> В слайдах встречается `std::cout << test.get_priv_field;` — это ошибка, метод нужно вызывать: `test.get_priv_field()`. Без скобок это не вызов, а обращение к самой функции-члену, и компилятор выдаст ошибку.

Слово `const` после списка параметров обещает, что метод не изменит поля объекта; такие методы можно вызывать и у константных объектов. В слайдах его нет, но для геттеров это обычная практика. Обращение к закрытому полю снаружи даёт ошибку: `error: 'int Q::x' is private within this context`.

### Модификаторы у конструкторов

Модификаторами можно помечать любые члены, в том числе конструкторы. Если **все** конструкторы класса `private` или `protected`, создать объект во внешнем коде нельзя:

```cpp
class TestClass
{
private:
    TestClass() { }
};

// TestClass test;  // ошибка доступа
```

Это используют намеренно, например, в паттерне «одиночка» или фабричных методах: объект создаёт только сам класс, причём внутри его собственных (в том числе статических) методов приватный конструктор доступен:

```cpp
class Config
{
    int value;
    Config(int v) : value(v) {}      // закрытый конструктор
public:
    static Config make(int v) { return Config(v); }  // внутри класса можно
    int get() const { return value; }
};

// Config c(1);                   // ошибка: конструктор private
Config c = Config::make(42);      // работает
// std::cout << c.get();          // Вывод: 42
```

### Модификатор по умолчанию. Класс против структуры

Если модификатор не указан, действует модификатор по умолчанию:

| | `class` | `struct` |
|---|---|---|
| Доступ по умолчанию | `private` | `public` |

Именно поэтому в классах мы в начале пишем `public:`. **Это единственное различие между классом и структурой**: у структур тоже могут быть методы и конструкторы, и всё сказанное о классах справедливо и для них. Исторически сложилось, что для сложных типов данных обычно используют `class`, а `struct` — для простых наборов полей, но это лишь соглашение.

```cpp
class C { int x = 7; };    // x — private по умолчанию
struct S { int x = 7; };   // x — public по умолчанию

// C c; c.x;   // ошибка доступа
S s; std::cout << s.x;     // Вывод: 7
```

> [!note] Деталь про наследование
> Модификатор по умолчанию отличается и при наследовании (у `class` — `private`, у `struct` — `public`); к этому вернёмся в теме [[05 Наследование и полиморфизм]].

## Задачи для практики

1. Напишите класс `Rectangle` с полями `width`, `height`, конструктором с параметрами и методами `area()` и `perimeter()`. Создайте несколько прямоугольников и выведите их площади.
2. Добавьте в `Account` метод `deposit(int)` и `withdraw(int)`: снятие не должно уводить баланс в минус (возвращайте `bool`). Решение: проверка `amount <= balance` перед вычитанием.
3. Сделайте так, чтобы нельзя было создать `Person` без имени: оставьте только конструктор с параметрами и убедитесь, что `Person p;` не компилируется.
4. Перепишите конструктор `Person` со списком инициализации и убедитесь, что поведение не изменилось.

## Частые ошибки

- Забыть, что при наличии своего конструктора пропадает конструктор по умолчанию — `Person p;` перестаёт компилироваться.
- Написать `age = age;` в методе с параметром `age` вместо `this->age = age;`.
- Указать возвращаемый тип у конструктора.
- Обращаться к `private`-полю извне вместо вызова геттера/сеттера.
- Забыть `;` после закрывающей `}` класса.
- Оставить поля встроенных типов неинициализированными.

## Кратко (шпаргалка)

- Класс = данные (поля) + поведение (методы); объект = экземпляр класса.
- `obj.field`, `obj.method()`; внутри метода — `this->field`.
- Конструктор: имя класса, без типа результата, вызывается при создании; есть конструктор по умолчанию (пустой, без параметров), если своих нет.
- `private` — только внутри класса; `protected` — плюс наследники; `public` — всем.
- `class`: по умолчанию `private`; `struct`: по умолчанию `public` — других отличий нет.
- Приватные поля + публичные геттеры/сеттеры.
