# Динамический массив, списки, деки

> [!abstract] О чём заметка
> Обычный массив быстро читается по индексу, но не умеет менять размер. В заметке строятся две базовые структуры данных, которые это исправляют: **динамический массив** (dynamic array) с амортизированным $O(1)$ добавлением в конец и **связный список** (linked list) с $O(1)$ вставкой и удалением на концах. На их основе определяются очередь, стек и дек (deque). Заметка сравнивает операции по сложности и объясняет, почему «одинаковое» $O(n)$ на практике бывает разным.

Предварительно полезно знать оценку сложности ([[01 Алгоритмическая сложность]]), указатели и динамическую память ([[08 Указатели и динамическая память]]) и деструкторы/RAII ([[02 Жизненный цикл объекта и RAII]]).

## Динамический массив

### Что не так с обычным массивом

Доступ к ячейке по индексу в массиве — $O(1)$, но **размер менять нельзя**. Хочется получить операции:

- `append(e)` — добавить элемент в конец;
- `removeEnd()` — удалить последний элемент;

при этом индексация `[i]` по-прежнему должна работать за $O(1)$.

### Наивная реализация

Раз изменить размер массива нельзя, создаём новый и копируем туда старое:

- `append(25)`: создаём массив длины $n+1$, копируем в него старый, дописываем элемент;
- `removeEnd()`: создаём массив длины $n-1$ и копируем все элементы, кроме последнего.

```text
DynamicArray {
    data: []                              # внутренний массив

    [i]:  return data[i]
    append(e):
        new_data = [длина(data)+1 нулей]
        скопировать data в new_data
        data = new_data
        data[конец] = e
    removeEnd():
        new_data = [длина(data)-1 нулей]
        скопировать data без последнего в new_data
        data = new_data
}
```

Сложность: `[i]` — $O(1)$; `append` и `removeEnd` — $O(n)$, так как копируется весь массив. Последовательное добавление $n$ элементов — $1 + 2 + \dots + n$ копирований, то есть $O(n^2)$.

### Улучшение: запас по ёмкости

**Идея.** При нехватке места увеличиваем внутренний массив **вдвое** и держим запас. Теперь внутренний массив длины 8 может «притворяться» массивом из 5 элементов: заполнена только часть, остальное — запас. Храним индекс последнего заполненного элемента (или размер).

```text
data:  11 23 36 17 48 .  .  .
индекс: 0  1  2  3  4  5  6  7        размер = 5, ёмкость = 8
```

Пока в запасе есть место, `append` — это запись в первую свободную ячейку, $O(1)$, без копирования. Когда запас кончился (`size == capacity`), создаём массив вдвое больше, копируем и дописываем.

Разбор добавления 9 элементов (ёмкость и копирования):

| Добавляем | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| Ёмкость после | 1 | 2 | 4 | 4 | 8 | 8 | 8 | 8 | 16 |
| Копирование? | нет | да (1) | да (2) | нет | да (4) | нет | нет | нет | да (8) |

### Амортизационный анализ

**Худший случай** одной операции `append` по-прежнему $O(n)$ (когда нужно расширять массив). Но расширения случаются редко — только на размерах, равных степеням двойки. Суммарное число копирований при добавлении $n$ элементов:

$$1 + 2 + 4 + \dots + \frac{n}{2} < n,$$

то есть $O(n)$ на $n$ операций, а на одну операцию в среднем $O(1)$. Такая оценка называется **амортизированной** (amortized), а метод её получения — **амортизационным анализом**. Итог:

| Подход | $n$ добавлений подряд | Одно добавление |
|---|---|---|
| Наивный | $O(n^2)$ | всегда $O(n)$ |
| Удвоение | $O(n)$ | амортизированно $O(1)$, в худшем случае $O(n)$ |

Цена — до $O(n)$ «лишних» ячеек в запасе. Асимптотика памяти остаётся $O(n)$, это приемлемая плата.

### Удаление с конца и ловушка «уменьшать на половине»

Удаляя последний элемент, достаточно уменьшить `size` — ячейка становится частью запаса. Чтобы не хранить огромный пустой массив, при большом запасе внутренний массив нужно уменьшать.

**Плохая идея:** уменьшать вдвое, когда массив заполнен меньше чем наполовину. Рассмотрим массив только что расширившийся: из 4 в 8 элементов, заполнено 5. Делаем `removeEnd` — заполнено 4 из 8, массив сжимается до 4. Теперь `append` — снова расширение до 8. Чередуя `append` и `removeEnd`, мы **каждый раз** копируем весь массив — амортизированная $O(1)$ превращается в $O(n)$.

**Правильное решение:** уменьшать вдвое, только когда массив заполнен **меньше чем на треть**. Тогда после сжатия он заполнен ещё примерно наполовину, и до следующего расширения или сжатия пройдёт не менее порядка $(\tfrac12 - \tfrac13)n$ операций — копирование амортизируется. Оба действия, `append` и `removeEnd`, снова амортизированно $O(1)$.

### Реализация на C++

```cpp
#include <algorithm>
#include <iostream>
#include <stdexcept>
using namespace std;

class DynamicArray {
    int* data_;
    size_t cap_;      // ёмкость внутреннего массива
    size_t size_;     // сколько элементов реально хранится

    void resize(size_t newCap) {
        int* nd = new int[newCap];
        copy(data_, data_ + size_, nd);   // O(size)
        delete[] data_;
        data_ = nd;
        cap_ = newCap;
        cout << "  [realloc -> cap " << cap_ << "]\n";
    }
public:
    DynamicArray() : data_(new int[1]), cap_(1), size_(0) {}
    DynamicArray(const DynamicArray&) = delete;            // правило трёх: копировать не умеем
    DynamicArray& operator=(const DynamicArray&) = delete;
    ~DynamicArray() { delete[] data_; }

    int& operator[](size_t i) {
        if (i >= size_) throw out_of_range("index");       // граница — по заполненной части
        return data_[i];
    }
    size_t size() const { return size_; }
    size_t capacity() const { return cap_; }

    void append(int e) {
        if (size_ == cap_) resize(2 * cap_);               // запас кончился — удваиваем
        data_[size_++] = e;
    }
    void removeEnd() {
        if (size_ == 0) throw out_of_range("empty");
        --size_;
        if (size_ < cap_ / 3) resize(max<size_t>(1, cap_ / 2));   // < 1/3 заполнено — вдвое меньше
    }
};

int main() {
    DynamicArray a;
    for (int i = 1; i <= 9; ++i) { cout << "append " << i << "\n"; a.append(i); }
    cout << "size=" << a.size() << " cap=" << a.capacity() << "\n";
    for (int i = 0; i < 6; ++i) { cout << "removeEnd\n"; a.removeEnd(); }
    cout << "size=" << a.size() << " cap=" << a.capacity() << "\n";
}
```

Вывод (сокращённо): расширения на `append 2` (cap 2), `3` (cap 4), `5` (cap 8), `9` (cap 16); после 9 добавлений `size=9 cap=16`. Затем при пятом `removeEnd` (размер 4 < 16/3) происходит сжатие до 8. Итог: `size=3 cap=8`.

> [!warning] Копирование класса
> Класс владеет сырым указателем, поэтому копирование явно запрещено. Без этого скопированный объект и оригинал удалили бы один и тот же массив. Подробности — в [[02 Жизненный цикл объекта и RAII]] и [[04 Move-семантика]].

### Вставка и удаление в произвольном месте

Вставка и удаление в середине остаются **$O(n)$**: нужно сдвинуть все элементы правее позиции.

```text
исходный:        D U R C
add(1, 'A'):     D A U R C       (U, R, C сдвинулись вправо)
remove(2):       D A R C         (из D A U R C убрали U; R и C сдвинулись влево)
```

**Итог:** динамический массив работает как обычный массив для индексации ($O(1)$) и дополнительно умеет добавлять и удалять в конце в среднем за $O(1)$. В C++ это `std::vector` ([[06 STL часть 1]]); его ёмкость растёт ступеньками (в типичной реализации — вдвое: 1, 2, 4, 8, 16, 32).

## Списки

**Список** (list) — не одна структура, а семейство структур данных, умеющих минимум:

| Операция | Смысл |
|---|---|
| `add` | добавить элемент |
| `remove` | удалить элемент |
| `get` | получить элемент по номеру |
| `set` | заменить элемент по номеру |

Динамический массив — один из способов реализовать список. Другой — связный список.

### Связный список

**Идея.** Каждый элемент хранится в отдельной «обёртке» — **узле** (node), которая знает значение, ссылку на предыдущий и ссылку на следующий узел. Сам список хранит ссылки на первый (`head`) и последний (`tail`) узлы. Такой список называют **двусвязным**.

```text
        head                                              tail
         |                                                 |
null <- [С] <-> [П] <-> [И] <-> [С] <-> [О] <-> [К] -> null
```

```text
Node {
    e: значение,
    prev: ссылка на предыдущий или пусто,
    next: ссылка на следующий или пусто
}
LinkedList {
    head: ссылка на первый или пусто,
    tail: ссылка на последний или пусто,
    size: размер
}
```

### get / set

В отличие от массива, доступ по индексу — **$O(n)$**: чтобы дойти до узла с номером $i$, нужно сделать $O(i)$ шагов по ссылкам с начала (или с конца). Только к первому и последнему элементам доступ $O(1)$ — ссылки на них хранит сам список.

> [!example] Задача: обнулить элементы на чётных индексах
> Если для каждого чётного $i$ вызывать `set(i, 0)`, каждый вызов идёт с начала, и получится $O(n^2)$. Лучше **один раз пройти по списку** и менять нужные узлы по месту: в узле, где мы уже стоим, изменение $O(1)$. Итого $O(n)$.

### add / remove

- **В начало или конец** — $O(1)$: меняем ссылки у крайнего узла и у самого списка.
- **В произвольное место** — $O(n)$ на то, чтобы дойти до узла, плюс $O(1)$ на перекидывание ссылок.
- **Удаление с начала или с конца** — $O(1)$ (двусвязность даёт доступ к предпоследнему узлу без прохода).
- **Удаление из произвольного места** — $O(n)$ дойти + $O(1)$ перекинуть ссылки.

### Реализация на C++

```cpp
#include <iostream>
#include <stdexcept>
using namespace std;

class LinkedList {
    struct Node {
        int e;
        Node* prev;
        Node* next;
        Node(int v) : e(v), prev(nullptr), next(nullptr) {}
    };
    Node* head_ = nullptr;
    Node* tail_ = nullptr;
    size_t size_ = 0;

    Node* nodeAt(size_t i) const {           // идём с ближнего конца: всё равно O(n)
        if (i >= size_) throw out_of_range("index");
        Node* cur;
        if (i < size_ / 2) { cur = head_; while (i--) cur = cur->next; }
        else { cur = tail_; for (size_t k = size_ - 1; k > i; --k) cur = cur->prev; }
        return cur;
    }
public:
    LinkedList() = default;
    LinkedList(const LinkedList&) = delete;
    LinkedList& operator=(const LinkedList&) = delete;
    ~LinkedList() { while (head_) removeHead(); }   // освобождаем все узлы

    size_t size() const { return size_; }
    int  get(size_t i) const { return nodeAt(i)->e; }
    void set(size_t i, int v) { nodeAt(i)->e = v; }

    void addHead(int v) {
        Node* n = new Node(v);
        n->next = head_;
        if (head_) head_->prev = n; else tail_ = n;   // список был пуст — n и голова, и хвост
        head_ = n; ++size_;
    }
    void addTail(int v) {
        Node* n = new Node(v);
        n->prev = tail_;
        if (tail_) tail_->next = n; else head_ = n;
        tail_ = n; ++size_;
    }
    int removeHead() {
        if (!head_) throw out_of_range("empty");
        Node* n = head_; int v = n->e;
        head_ = n->next;
        if (head_) head_->prev = nullptr; else tail_ = nullptr;
        delete n; --size_;
        return v;
    }
    int removeTail() {
        if (!tail_) throw out_of_range("empty");
        Node* n = tail_; int v = n->e;
        tail_ = n->prev;
        if (tail_) tail_->next = nullptr; else head_ = nullptr;
        delete n; --size_;
        return v;
    }
    void insert(size_t i, int v) {           // вставка перед позицией i
        if (i > size_) throw out_of_range("index");
        if (i == 0) { addHead(v); return; }
        if (i == size_) { addTail(v); return; }
        Node* at = nodeAt(i);                // O(n): добраться
        Node* n = new Node(v);               // O(1): перекинуть 4 ссылки
        n->prev = at->prev; n->next = at;
        at->prev->next = n; at->prev = n;
        ++size_;
    }
    void zeroEven() {                        // O(n): один проход
        size_t i = 0;
        for (Node* c = head_; c; c = c->next, ++i) if (i % 2 == 0) c->e = 0;
    }
    void print() const {
        for (Node* c = head_; c; c = c->next) cout << c->e << (c->next ? " <-> " : "\n");
    }
};

int main() {
    LinkedList d;
    d.addTail(1); d.addTail(2); d.addTail(3); d.addHead(0);
    d.print();                         // Вывод: 0 <-> 1 <-> 2 <-> 3
    d.insert(2, 99); d.print();        // Вывод: 0 <-> 1 <-> 99 <-> 2 <-> 3
    cout << d.get(2) << "\n";          // Вывод: 99
    d.zeroEven(); d.print();           // Вывод: 0 <-> 1 <-> 0 <-> 2 <-> 0
}
```

Самое частое место ошибок — **граничные случаи**: вставка в пустой список, удаление единственного узла (нужно обнулить и `head`, и `tail`), забытый `delete` узла.

## Динамический массив против связного списка

| Операция | Динамический массив | Связный список |
|---|---|---|
| Добавление в конец | в среднем $O(1)$ | $O(1)$ |
| Добавление в начало | $O(n)$ | $O(1)$ |
| Добавление в произвольное место | $O(n)$ | $O(1)$, если уже дошли до узла; иначе $O(n)$ |
| Удаление с конца | в среднем $O(1)$ | $O(1)$ |
| Удаление с начала | $O(n)$ | $O(1)$ |
| Удаление из произвольного места | $O(n)$ | $O(n)$ |
| Доступ по индексу | $O(1)$ | $O(n)$ |

> [!note] Не всё решает $O(n)$
> $O(n)$ описывает лишь **характер роста**, а не скорость. Даже там, где у обеих структур $O(n)$, массив часто быстрее: его элементы лежат в памяти подряд (процессор эффективно читает соседние ячейки), а в списке каждый переход — прыжок по ссылке в произвольное место памяти. Список к тому же тратит память на две ссылки на каждый элемент. Поэтому по умолчанию в C++ берут `std::vector`, а список — когда действительно нужны частые вставки и удаления по уже известному положению.

## Очереди, стеки, деки

Эти три структуры — не способ хранения, а **интерфейс**: набор допустимых операций.

**Очередь** (queue) — «первым пришёл, первым ушёл» (FIFO). Операции: `add` — встать в конец, `next` — взять первого.

**Стек** (stack, «стопка») — «последним пришёл, первым ушёл» (LIFO). Операции: `push` — положить сверху, `pop` — снять верхний.

**Дек** (deque, double-ended queue — «очередь с двумя концами») — в него можно добавлять и из него убирать элементы с **обоих** концов: `addHead`, `addTail`, `nextHead`, `nextTail`. Очередь и стек выражаются через дек:

| Операция стека | через дек | Операция очереди | через дек |
|---|---|---|---|
| `push` | `addTail` | `add` | `addHead` |
| `pop` | `nextTail` | `next` | `nextTail` |

(для очереди направление можно выбрать зеркально — важно, чтобы добавление и извлечение были на разных концах).

```cpp
// продолжение предыдущей программы: стек и очередь на двусвязном списке
LinkedList st; st.addTail(1); st.addTail(2); st.addTail(3);
cout << st.removeTail() << st.removeTail() << st.removeTail() << "\n";  // Вывод: 321 (LIFO)
LinkedList q; q.addHead(1); q.addHead(2); q.addHead(3);
cout << q.removeTail() << q.removeTail() << q.removeTail() << "\n";    // Вывод: 123 (FIFO)
```

**Дек на связном списке.** Все четыре операции дека соответствуют вставке/удалению на концах списка, то есть $O(1)$:

| Операция дека | Операция списка | Сложность |
|---|---|---|
| `addHead` | вставка в начало | $O(1)$ |
| `nextHead` | удаление с начала | $O(1)$ |
| `addTail` | вставка в конец | $O(1)$ |
| `nextTail` | удаление с конца | $O(1)$ |

Просто заменить список на динамический массив **без ухудшения** не получится: `addHead` и `nextHead` превратятся в $O(n)$ из-за сдвига всех элементов.

### В стандартной библиотеке

```cpp
#include <deque>
#include <list>
#include <queue>
#include <stack>
#include <vector>

std::vector<int> v;      // динамический массив
std::list<int> l;        // двусвязный список
std::deque<int> d;       // дек: push_front / push_back / pop_front / pop_back, доступ [i] за O(1)
std::stack<int> s;       // адаптер: push / pop / top
std::queue<int> q;       // адаптер: push / pop / front
```

> [!note] `std::deque` внутри
> `std::deque` в стандартной библиотеке устроен не как список, а как набор блоков фиксированного размера: благодаря этому он даёт и $O(1)$ вставку на обоих концах, и $O(1)$ доступ по индексу. Подробнее о контейнерах — в [[06 STL часть 1]] и [[07 STL часть 2]].

## Частые ошибки

- **Расширять массив на константу** (`+1`, `+10`) вместо умножения — вырождение в $O(n^2)$.
- **Сжимать массив при заполнении на половину** — «дребезг» из расширений и сжатий; порог — треть.
- **Границы:** проверять `i < size`, а не `i < capacity`.
- **Забыть про `head`/`tail` в граничных случаях** списка: пустой список, единственный элемент.
- **Утечка узлов:** без деструктора, освобождающего все узлы, память не вернётся.
- **Считать список всегда быстрее массива:** он выигрывает только на вставках/удалениях по готовому положению.

## Задачи для практики

2. Обнулить элементы на чётных индексах списка за $O(n)$. *Решение: один проход с счётчиком индекса (`zeroEven`).*
3. Реализовать стек и очередь поверх двусвязного списка. *Решение: см. раздел «Очереди, стеки, деки».*
4. Объяснить, почему нельзя сжимать массив при заполнении на половину. *Ответ: чередование `append`/`removeEnd` на границе даёт копирование на каждой операции.*
5. Почему `get(i)` в списке $O(n)$, а в массиве $O(1)$? *Ответ: массив вычисляет адрес по формуле, список идёт по ссылкам.*

## Кратко (шпаргалка)

- Динамический массив: ёмкость с запасом, удвоение при заполнении, сжатие вдвое при заполнении меньше трети.
- `append`/`removeEnd` — амортизированно $O(1)$, индекс — $O(1)$, вставка/удаление в середине и в начале — $O(n)$.
- Связный список: узлы со ссылками `prev`/`next`, `head` и `tail`; концы — $O(1)$, индекс — $O(n)$.
- Очередь (FIFO), стек (LIFO), дек (оба конца) — интерфейсы; все выражаются через дек на двусвязном списке за $O(1)$.
- $O(n)$ у массива на практике обычно быстрее $O(n)$ у списка из-за расположения в памяти.
