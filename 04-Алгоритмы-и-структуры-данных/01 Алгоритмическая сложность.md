# Алгоритмическая сложность

> [!abstract] О чём заметка
> **Алгоритмическая сложность** (algorithmic complexity) показывает, как растёт время работы и расход памяти алгоритма при увеличении размера входных данных. Это главный инструмент сравнения алгоритмов: секунды зависят от компьютера, а характер роста — нет. Заметка вводит нотацию $O(\dots)$, двоичный логарифм, правила подсчёта сложности и разбирает на примерах линейный, квадратичный и логарифмический алгоритмы (бинарный поиск).

## Алгоритм, массив, псевдокод

**Алгоритм** — придуманная последовательность шагов, выполнив которую, программа решит поставленную задачу. Например, «получить массив и переставить элементы так, чтобы он оказался отсортированным» (см. [[03 Сортировки]]).

Изучение алгоритмики помогает мыслить как программист, проектировать быстрые алгоритмы, уверенно применять стандартные структуры данных и проходить технические собеседования.

**Массив** — пронумерованный набор элементов фиксированного размера. Нумерация идёт с 0, поэтому у массива длины $n$ последний элемент имеет номер $n-1$:

```text
значения: 1  3  4  6  7  8  10 13 14
индексы:  0  1  2  3  4  5  6  7  8      n = 9, последний индекс = 8
```

Менять значения элементов можно, а вот размер массива — нет, поэтому «добавить элемент в конец» обычному массиву недоступно (как обойти это ограничение — в [[04 Динамический массив, списки, деки]]). Подробнее про массивы в C++ см. [[04 Массивы]].

**Псевдокод** (pseudocode) — условный язык, предназначенный для чтения человеком, а не компьютером. Его синтаксис не строг и не привязан к конкретному языку:

```text
max(a, b):
    if a > b
        return a
    else
        return b
```

В этой заметке алгоритмы даются псевдокодом, а затем кодом на C++.

## Что такое сложность и как её измерять

Алгоритмы отличаются двумя ресурсами: **временем выполнения** и **используемой памятью**. Вместе это и называется алгоритмической сложностью.

Измерять время секундами бессмысленно: на новом ноутбуке программа пойдёт быстрее, чем на старом, а при множестве параллельных программ — медленнее. Считать «простые операции» тоже слишком муторно даже для небольших программ. Поэтому в алгоритмике смотрят, **как меняется время работы при росте размера входных данных** $n$.

Если при увеличении входа в 100 раз время тоже растёт примерно в 100 раз, говорят, что время работы $O(n)$ — **линейное**. Такой характер роста называют **асимптотикой** (asymptotics). Память измеряют так же: если дополнительная память не зависит от $n$ (несколько переменных), она **константная**, $O(1)$.

## Пример 1. Поиск максимума — $O(n)$

**Идея.** Берём первый элемент как кандидата и проходим по массиву; если встретили больший — обновляем кандидата.

Трассировка на массиве `13 42 67 43 89 90 67`:

| Просмотрен элемент | 13 | 42 | 67 | 43 | 89 | 90 | 67 |
|---|---|---|---|---|---|---|---|
| Текущий максимум | 13 | 42 | 67 | 67 | 89 | 90 | 90 |

Псевдокод:

```text
max = arr[0]
for i от 1 до n-1
    if arr[i] > max
        max = arr[i]
print "Максимум:" max
```

```cpp
#include <iostream>
#include <vector>
using namespace std;

int findMax(const vector<int>& arr) {
    int mx = arr[0];                    // первый кандидат
    for (size_t i = 1; i < arr.size(); ++i)
        if (arr[i] > mx) mx = arr[i];   // инвариант: mx — максимум среди просмотренных
    return mx;
}

int main() {
    cout << findMax({13, 42, 67, 43, 89, 90, 67}) << "\n";   // Вывод: 90
}
```

> [!note] Инвариант
> **Инвариант** — утверждение, остающееся истинным во время всей работы алгоритма. Здесь: «после каждой итерации в `mx` лежит максимум среди всех просмотренных элементов». По окончании цикла просмотрены все элементы, значит `mx` — ответ. Инвариант — основной способ доказать **корректность** алгоритма.

**Сложность.** Один проход, на каждый элемент — одно сравнение: время $O(n)$. Дополнительная память — `mx` и `i`: $O(1)$. Если увеличить массив в 100 раз, время вырастет примерно в 100 раз.

## Пример 2. Неуникальные значения — $O(n^2)$

**Задача.** Дан массив ежедневных замеров температуры. Найти, сколько дней имеют «неуникальную» температуру, то есть такую, которая встретилась ещё хотя бы раз. Для `13 12 7 14 12 14 15` ответ 4 (две двенадцатых и две четырнадцатых).

**Идея.** Для каждого дня $i$ перебираем все остальные $j \ne i$; если нашли равное значение — день неуникален.

```text
count = 0
for i от 0 до n-1
    for j от 0 до n-1
        if arr[i] == arr[j] И i != j
            count += 1
            завершить внутренний цикл     # день уже посчитан, дальше искать незачем
print count
```

```cpp
#include <iostream>
#include <vector>
using namespace std;

int countNonUnique(const vector<int>& a) {
    int count = 0;
    for (size_t i = 0; i < a.size(); ++i)
        for (size_t j = 0; j < a.size(); ++j)
            if (a[i] == a[j] && i != j) { ++count; break; }   // break — «завершаем внутренний цикл»
    return count;
}

int main() {
    cout << countNonUnique({13, 12, 7, 14, 12, 14, 15}) << "\n";   // Вывод: 4
}
```

> [!warning] Без `break` ответ неверный
> Без досрочного выхода из внутреннего цикла `count` увеличивался бы на каждое совпадение, и день с тремя одинаковыми замерами засчитался бы дважды.

**Сложность.** Двойной цикл по $n$ элементов — $n \cdot n$ операций, то есть $O(n^2)$ — **квадратичное** время. При увеличении данных в 10 раз операций станет в 100 раз больше. Для $n = 10^9$ при условной скорости «1 сек на $n$» это порядка миллиона секунд. Память $O(1)$ (счётчик и два индекса).

Как ускорить такую задачу (например, с помощью хеш-таблицы) — см. [[06 Хеширование]].

## Двоичный логарифм

**Двоичный логарифм** $\log_2 x$ — это число, в которое нужно возвести 2, чтобы получить $x$. Например, $\log_2 8 = 3$, так как $2^3 = 8$.

Другое, более «алгоритмическое» определение: $\log_2 x$ — **сколько раз надо разделить $x$ пополам, чтобы получить 1**. Для 8: $8 \to 4 \to 2 \to 1$ — три деления.

Логарифм растёт очень медленно:

| $x$ | 8 | 32 | 64 | 256 | 1 024 | 4 294 967 296 |
|---|---|---|---|---|---|---|
| $\log_2 x$ | 3 | 5 | 6 | 8 | 10 | 32 |

Геометрически это высота «пирамиды» удвоений: на ширину 8 элементов приходится $1 + \log_2 8 = 4$ уровня, а всего узлов $2\cdot 8 - 1 = 15$. Эта картинка пригодится в [[03 Сортировки]] (дерево вызовов сортировки слиянием) и в [[05 Пирамиды и деревья поиска]].

## Пример 3. Бинарный поиск — $O(\log n)$

**Задача.** Дан массив длины $n$, отсортированный по возрастанию, и число $x$. Найти номер ячейки с $x$ (или сообщить, что его нет).

**Наивное решение** — линейный просмотр: если встретили `x`, нашли, иначе дошли до конца. Время $O(n)$, память $O(1)$; свойство отсортированности не используется.

**Идея бинарного поиска** (binary search). Слово в словаре не ищут постранично с начала: открывают середину, по ней определяют, слева или справа искомое слово, и повторяют для оставшейся половины. Так же с массивом: сравниваем `x` со средним элементом и отбрасываем половину, в которой `x` заведомо быть не может.

Трассировка: ищем 4 в `1 3 4 6 7 8 10 13 14` (индексы 0..8):

| Шаг | Отрезок `[left, right]` | `mid` | `arr[mid]` | Решение |
|---|---|---|---|---|
| 1 | [0, 8] | 4 | 7 | $4 < 7$ — ищем слева, `right = 3` |
| 2 | [0, 3] | 1 | 3 | $4 > 3$ — ищем справа, `left = 2` |
| 3 | [2, 3] | 2 | 4 | нашли, ответ 2 |

Псевдокод и код на C++:

```text
left = 0
right = длина(arr) - 1
while left <= right
    middle = (left + right) / 2
    if arr[middle] == x:  нашли, вернуть middle
    if arr[middle] >  x:  right = middle - 1     # ищем слева
    else:                 left  = middle + 1     # ищем справа
не нашли
```

```cpp
#include <iostream>
#include <vector>
using namespace std;

// возвращает индекс элемента или -1, если его нет
int binarySearch(const vector<int>& a, int x) {
    int left = 0, right = (int)a.size() - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;   // не (left+right)/2: сумма может переполнить int
        if (a[mid] == x) return mid;
        if (a[mid] > x) right = mid - 1;       // искомое левее середины
        else            left  = mid + 1;       // искомое правее середины
    }
    return -1;
}

int main() {
    vector<int> s = {1, 3, 4, 6, 7, 8, 10, 13, 14};
    cout << binarySearch(s, 4)  << "\n";   // Вывод: 2
    cout << binarySearch(s, 5)  << "\n";   // Вывод: -1
    cout << binarySearch(s, 14) << "\n";   // Вывод: 8
}
```

> [!warning] Условие цикла и границы
> В слайдах цикл записан как `while left < right` с последующей проверкой `arr[left]`. Это тоже рабочая схема, но она очень чувствительна к мелочам: при `left < right` и `right = middle - 1` легко потерять последний кандидат. Проще и надёжнее держать инвариант «если `x` есть, он лежит в `[left, right]`» и писать `while (left <= right)`, как выше.

**Сложность.** На каждом шаге смотрим на один элемент и вдвое сокращаем отрезок. Сколько раз можно разделить $n$ пополам? Ровно $\log_2 n$. Итого время $O(\log n)$, память $O(1)$. Для массива из $4\cdot 10^9$ элементов хватит около 32 сравнений.

> [!tip] Готовая реализация
> В стандартной библиотеке есть `std::binary_search`, `std::lower_bound` и `std::upper_bound` — см. [[06 STL часть 1]] и [[07 STL часть 2]].

## Правила подсчёта сложности

1. **Повторы — умножаем.** Действие за $O(X)$, повторённое $Y$ раз, стоит $O(Y \cdot X)$. (Цикл по $n$ с вложенным циклом по $n$: $O(n \cdot n) = O(n^2)$.)
2. **Друг за другом — складываем.** Действия за $O(X)$ и $O(Y)$, выполненные подряд, дают $O(X + Y)$.
3. **Сумма нескольких слагаемых — оставляем самое быстрорастущее.** $O(2^n \cdot n + n^3 + n + \log n)$ записывается как $O(2^n \cdot n)$.
4. **Множители-константы выбрасываем.** $O(13n)$ — это $O(n)$.

Порядок роста основных классов (по возрастанию):

$$1 \;<\; \log n \;<\; n \;<\; n \log n \;<\; n^2 \;<\; n^3 \;<\; \dots \;<\; 2^n$$

| Сложность | Название | Типичный пример |
|---|---|---|
| $O(1)$ | константная | обращение к элементу массива по индексу |
| $O(\log n)$ | логарифмическая | бинарный поиск |
| $O(n)$ | линейная | поиск максимума, линейный поиск |
| $O(n \log n)$ | линеарифмическая | сортировка слиянием, быстрая сортировка |
| $O(n^2)$ | квадратичная | сортировка пузырьком, двойной цикл по массиву |
| $O(2^n)$ | экспоненциальная | наивная рекурсия в задаче о монетках |

> [!note] Что означает $O$
> $O(\cdot)$ описывает только **характер роста**, а не точное время. Два алгоритма с $O(n)$ могут отличаться по скорости в несколько раз: именно константа, которую мы «выбросили», и особенности работы с памятью (скачки по ссылкам медленнее, чем проход по массиву) решают дело на практике. Поэтому асимптотика — ориентир, но не замена измерений.

## Частые ошибки

- **Измерять «скорость» секундами** и сравнивать алгоритмы на одной машине и одном входе, не думая о росте.
- **Забыть про память:** алгоритм, быстрый по времени, может требовать $O(n^2)$ памяти (см. предподсчёт в [[02 Динамическое программирование и жадные алгоритмы]]).
- **Применить бинарный поиск к неотсортированному массиву** — результат будет неверным.
- **Ошибки в границах** бинарного поиска (`left < right` против `left <= right`, `middle ± 1`) и переполнение в `(left + right) / 2`.
- **Складывать вместо умножения** для вложенных циклов и наоборот.

## Задачи для практики

1. Массив длиной 10: чем будет последний индекс? *Ответ: 9 ($n-1$).*
2. Определите по псевдокоду, что делает `max(a, b)` из примера выше. *Ответ: возвращает большее из двух чисел.*
3. Чему равен $\log_2 64$? *Ответ: 6.*
4. Оцените сложность: цикл по $n$ элементов, затем отдельный двойной цикл по $n$. *Ответ: $O(n + n^2) = O(n^2)$ по правилам сложения и «вычёркивания».*
5. Сколько шагов в худшем случае сделает бинарный поиск по $10^6$ элементам? *Ответ: около $\log_2 10^6 \approx 20$.*

## Кратко (шпаргалка)

- Сложность = рост времени и памяти с ростом размера входа $n$, а не секунды.
- Поиск максимума — $O(n)$ по времени, $O(1)$ по памяти; поиск пар — $O(n^2)$; бинарный поиск — $O(\log n)$ (нужен отсортированный массив).
- $\log_2 n$ — сколько раз можно поделить $n$ пополам до 1.
- Вложенное — умножаем, последовательное — складываем, оставляем старшее слагаемое, константы отбрасываем.
- Порядок: $1 < \log n < n < n\log n < n^2 < n^3 < 2^n$.
- Инвариант помогает доказывать корректность.
