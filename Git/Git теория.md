# Ветка в Git
Опция в Git, которая позволяет создавать "Параллельную реальность" в проектах когда:
1. Над проектом работает несколько человек  
2. каждый делает свою задачу  
3. чтобы не мешать друг другу, каждый работает в своей ветке  
4. когда задача готова, то всё сливается в основную ветку 
# Зачем нужно ветвление в Git
| Исключение поломок                                                                  | Решение конфликтов                                                                                       |
| ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Помогает избежать  <br>поломок в основном  <br>проекте, пока функция  <br>не готова | Избавляет от конфликтов,  <br>когда несколько человек  <br>исправляют одну и ту же  <br>часть по-разному |
# Решение конфликтов
Решение конфликтов:
1. После merge где написано CONFLICT смотрим в каком файле конфликт
2. Открываем файл
3. Удаляем системную разметку (Слеши, тире, равно, командные слова и тд. чего быть не должно)
4. Выбираем что оставить, можем оставить всё, удалить всё, оставить что то одно. Решаем сами
5. Делаем новый коммит, с отслеживанием файла(если пишем 2умя командами, то с начала git add потом коммит)

# .gitignore
Это файл настройки, создаётся в папке проекта. В нём указывается какие файлы нужно игнорировать при публикации на GitHub.
[[Правило записи файлов в gitignore и доп. информация]]
# Настройка .gitignore, если файл проиндексирован  
1. Добавьте нужное правило в .gitignore  
2. Уберите файл из индекса, удалите из отслеживаемых. Для этого воспользуйтесь командой git rm --cached имя-файла. При помощи команды git rm с ключом --cached мы удаляем  файл из индекса, из отслеживаемых, но оставляем его на компьютере  
3. Теперь сработает правило игнорирования и Git перестанет следить за файлом или папкой
