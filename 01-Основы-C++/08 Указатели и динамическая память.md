# Указатели и динамическая память

> [!abstract] О чём заметка
> Динамическая память — это память, которую программист сам запрашивает у операционной системы во время работы программы и сам возвращает обратно. Она нужна, когда размер данных неизвестен заранее или когда данные должны пережить функцию, в которой созданы. Разберём `malloc`/`calloc`/`free`, операторы `new`/`delete`, динамические массивы и двумерные динамические массивы.

## Что такое динамическая память

В [[09 Модель памяти]] выделяют три вида памяти: статическую, автоматическую (стек) и динамическую. Автоматические переменные исчезают, когда заканчивается блок, где они объявлены. **Динамическая память (heap, «куча»)** живёт, пока вы сами её не освободите. Порядок работы всегда один:

1. **запросить** память у ОС;
2. **использовать** её через указатель (см. [[07 Указатели и массивы]]);
3. **вернуть** (освободить).

> [!warning] Утечка памяти
> Если забыть освободить память, она останется занятой до конца программы. Это **утечка памяти (memory leak)**. В долгоживущих программах утечки накапливаются и могут исчерпать оперативную память.

Размер динамического массива определяется **во время выполнения** (например, вводится пользователем), а у локального массива он должен быть известен при компиляции.

## Способ 1: malloc, calloc, free

Это старые функции языка C. Они объявлены в `<cstdlib>` (подключается и через `<iostream>`, но лучше написать явно).

### malloc

`malloc(n)` запрашивает **n байт** и возвращает указатель на выделенную область типа `void*` — «указатель на неизвестно что». Чтобы работать с памятью, `void*` нужно привести к указателю нужного типа через `static_cast` (см. [[05 Функции и рекурсия]]).

Аргумент — число **байт**, не элементов. В 20 байт поместится всего 5 `int` (по 4 байта). Чтобы не считать вручную, используйте `sizeof`:

```cpp
int* int_ptr = static_cast<int*>(malloc(26 * sizeof(int)));        // 26 целых чисел
double* dbl_ptr = static_cast<double*>(malloc(13 * sizeof(double))); // 13 вещественных
```

Смена типа элементов требует менять только аргумент `sizeof`.

`malloc` **не инициализирует** память: там лежит «мусор» от прежних данных.

### calloc

`calloc(count, size)` — то же самое, но:

- принимает **два** аргумента: число элементов и размер одного элемента (то, что в `malloc` перемножается);
- заполняет память **нулями**.

```cpp
int* zeros = static_cast<int*>(calloc(20, sizeof(int)));   // 20 нулевых int
```

### free

`free(ptr)` освобождает память, выданную `malloc`/`calloc`:

```cpp
#include <cstdlib>
#include <iostream>

int main()
{
    int* int_ptr = static_cast<int*>(malloc(20 * sizeof(int)));   // массив на 20 int
    int_ptr[0] = 65;                                              // используем
    std::cout << int_ptr[0] << std::endl;                         // Вывод: 65
    free(int_ptr);                                                // освобождаем
    return 0;
}
```

> [!example] Найдите ошибки
> ```cpp
> int size = 15;
> float* flt_ptr = static_cast<int*>(calloc(size * sizeof(float)));
> flt_ptr[size] = 43.8;
> return 0;
> ```
> Здесь **четыре** проблемы: (1) указатель приводится к `int*`, а не `float*`; (2) у `calloc` должно быть два аргумента; (3) индекс `size` выходит за границы — последний элемент имеет индекс `size - 1`; (4) нет `free`. Правильно:
> ```cpp
> #include <cstdlib>
> #include <iostream>
>
> int main()
> {
>     int size = 15;
>     float* flt_ptr = static_cast<float*>(calloc(size, sizeof(float)));
>     flt_ptr[size - 1] = 43.8f;
>     std::cout << flt_ptr[size - 1] << std::endl;   // Вывод: 43.8
>     free(flt_ptr);
>     return 0;
> }
> ```

`malloc`, `calloc` и `free` — самые старые и не слишком удобные инструменты. В C++ есть более современные: `new` и `delete`.

## Способ 2: new и delete

Оператор `new <тип>` создаёт **одно** значение в динамической памяти и возвращает указатель на него. Освобождает память оператор `delete <указатель>`.

```cpp
#include <iostream>

int main()
{
    int* var = new int;      // память под один int
    *var = 50;               // пользуемся через указатель
    std::cout << *var << std::endl;   // Вывод: 50
    delete var;              // освобождаем
    return 0;
}
```

Значение можно задать сразу: `int* p = new int(50);` или инициализировать нулём: `new int();`.

Вместе с `delete` хорошо привыкнуть обнулять указатель: `delete var; var = nullptr;` — тогда случайное повторное использование хотя бы предсказуемо (разыменование `nullptr`), а повторный `delete nullptr` безвреден.

## Способ 3: new[] и delete[]

Для динамических массивов в C++ есть удобные операторы:

- `new <тип>[<количество>]` — выделяет массив (количество **элементов**, `sizeof` не нужен);
- `delete[] <указатель>` — освобождает массив.

```cpp
#include <iostream>

int main()
{
    int size = 5;
    int* a = new int[size];               // 5 элементов, значения не определены
    int* b = new int[5] {1, 2, 3, 4, 5};  // список инициализации (размер известен при компиляции)
    int* c = new int[5]();                // все нули — аналог calloc

    for (int i = 0; i < size; i++)
    {
        a[i] = i * i;
    }
    std::cout << a[4] << " " << b[4] << " " << c[4] << std::endl;   // Вывод: 16 5 0

    delete[] a;
    delete[] b;
    delete[] c;
    return 0;
}
```

> [!warning] Пары операторов нельзя смешивать
> Что выделено — тем и освобождать:
>
> | Выделили | Освободить |
> |---|---|
> | `malloc` / `calloc` | `free` |
> | `new` | `delete` |
> | `new[]` | `delete[]` |
>
> `delete` вместо `delete[]` (или `free` вместо `delete`) — неопределённое поведение.

## Динамическая память и функции

Локальные переменные уничтожаются при выходе из блока. Поэтому такой код **опасен**:

```cpp
int* create_arr()
{
    int arr[10];     // локальный (автоматический) массив
    return arr;      // возвращаем адрес памяти, которая сейчас будет освобождена!
}
```

После выхода из `create_arr` память под `arr` помечена как свободная, а указатель «висит» (dangling pointer): пользоваться им нельзя. Компилятор g++ предупредит: `address of local variable 'arr' returned`.

Чтобы вернуть массив из функции, создайте его динамически — он переживёт функцию. Но тогда **вызывающий код обязан его освободить**:

```cpp
#include <iostream>

int* create_arr(int size)
{
    int* arr = new int[size];
    for (int i = 0; i < size; i++)
    {
        arr[i] = i + 1;          // заполняем по порядку
    }
    return arr;                  // память остаётся жить
}

int main()
{
    int size = 0;
    std::cout << "Размер: ";
    std::cin >> size;            // например, ввели 5

    int* external_arr = create_arr(size);
    for (int i = 0; i < size; i++)
    {
        std::cout << external_arr[i] << " ";   // Вывод: 1 2 3 4 5
    }
    std::cout << std::endl;

    delete[] external_arr;       // без этого — утечка
    return 0;
}
```

> [!tip] Размер нужно носить с собой
> Указатель не знает, сколько элементов в массиве. Передавайте размер отдельной переменной или параметром, как в [[07 Указатели и массивы]].

## Двумерные динамические массивы

Двумерный динамический массив устроен иначе, чем автоматический `int a[3][4]`. Это **массив указателей на массивы**:

1. создаём одномерный массив указателей (`int*`) — по одному на строку;
2. для каждой строки создаём одномерный массив нужного типа;
3. адреса строк кладём в массив из п. 1.

Тип «массива указателей на `int`» — `int**` (см. указатели на указатели в [[07 Указатели и массивы]]).

```text
arr (int**)
 +------+     +---+---+---+---+
 | arr[0]|--->| . | . | . | . |   строка 0
 +------+     +---+---+---+---+
 | arr[1]|--->| . | . | 3 | . |   строка 1, arr[1][2] = 3
 +------+     +---+---+---+---+
 | arr[2]|--->| . | . | . | . |   строка 2
 +------+     +---+---+---+---+
```

Освобождение — в **обратном** порядке: сначала каждая строка, затем массив указателей.

```cpp
#include <iostream>

int main()
{
    int rows = 3, cols = 4;

    // создание
    int** arr = new int*[rows];            // массив указателей на строки
    for (int i = 0; i < rows; i++)
    {
        arr[i] = new int[cols]();          // строка из cols нулей
    }

    arr[1][2] = 3;                         // используем как обычную матрицу

    for (int i = 0; i < rows; i++)
    {
        for (int j = 0; j < cols; j++)
        {
            std::cout << arr[i][j] << " ";
        }
        std::cout << std::endl;
    }
    // Вывод:
    // 0 0 0 0
    // 0 0 3 0
    // 0 0 0 0

    // освобождение
    for (int i = 0; i < rows; i++)
    {
        delete[] arr[i];                   // каждая строка — отдельный кусок памяти
    }
    delete[] arr;                          // затем массив указателей
    return 0;
}
```

Если сделать только `delete[] arr`, строки останутся без владельца — утечка.

## Задачи для практики

1. **Массив пользовательского размера.** Спросите размер `n`, создайте `new int[n]`, заполните числами `1..n`, выведите, освободите. (Пример выше.)
2. **Таблица умножения.** Создайте матрицу `rows × cols`, заполните таблицей умножения, выведите, освободите всю память.
3. **Функция `int* make_filled(int n, int value)`**, возвращающая массив из `n` одинаковых чисел; в `main` освободите результат.
4. **Найдите утечки** в программе, где `new int[10]` вызывается в цикле без `delete[]`. Решение: добавьте `delete[]` в конце каждой итерации.

## Частые ошибки

- Забыть `free`/`delete`/`delete[]` — утечка памяти.
- Освободить не тем оператором (`delete` вместо `delete[]`, `free` для `new`).
- Освободить одну и ту же память дважды (double free) либо использовать её после освобождения.
- Вернуть из функции указатель на локальный массив.
- Выйти за границы: у массива из `n` элементов индексы `0 .. n-1`.
- Приводить результат `malloc` не к тому типу или забыть умножить на `sizeof`.
- Освободить в двумерном массиве только внешний `delete[] arr`.

## Кратко (шпаргалка)

| Задача | Выделение | Освобождение |
|---|---|---|
| Сырые байты (C-стиль) | `malloc(n * sizeof(T))` | `free(p)` |
| То же, с обнулением | `calloc(n, sizeof(T))` | `free(p)` |
| Одно значение | `new T` | `delete p` |
| Массив | `new T[n]`, `new T[n]()`, `new T[3]{...}` | `delete[] p` |
| Матрица | `new T*[r]` + `new T[c]` в цикле | `delete[]` строк, потом `delete[]` указателей |

- Динамическая память не освобождается сама — освобождаете вы.
- `malloc` считает в байтах, `new[]` — в элементах.
- Локальные массивы возвращать из функции нельзя, динамические — можно.
