# Область видимости и пространства имён

> [!abstract] О чём заметка
> Какие бывают виды памяти в программе (статическая, автоматическая, динамическая), что делает ключевое слово `static` и как пространства имён (`namespace`) помогают избежать конфликтов названий в больших программах.

## Три вида памяти

От вида памяти зависит, где она размещается, сколько её доступно, кто ею управляет и когда переменная создаётся.

| Вид | Что в ней лежит | Время жизни | Кто управляет |
|---|---|---|---|
| Статическая | глобальные и `static`-переменные | от старта до завершения программы | компилятор/ОС |
| Автоматическая | обычные локальные переменные, параметры, цепочка вызовов функций | пока жив блок (область видимости) | компилятор/ОС |
| Динамическая | то, что запрошено вручную | пока программист не освободит | программист |

Основы того, как переменные лежат в памяти: [[09 Модель памяти]].

## Статическая память

**Статическая память выделяется ещё до запуска программы, на этапе компиляции и сборки.** Адреса статических переменных фиксированы и не меняются, а создаются и инициализируются они **до входа в `main`**. Уничтожаются при завершении программы.

Статические переменные бывают двух видов: **глобальные** и **помеченные словом `static`**.

### Глобальные переменные

**Глобальная переменная** определена вне функций и не помечена `static`. Видна всему коду, ниже точки объявления:

```cpp
#include <iostream>

int glob_var = 100;        // создаётся до main со значением 100

void func() { glob_var = 10; }

int main()
{
    glob_var = 5;
    func();
    std::cout << glob_var << '\n';   // 10
}
```

Почему глобальных переменных стоит избегать, см. [[09 Модель памяти]].

### Переменные `static` вне функций

**`static`-переменная на уровне файла подобна глобальной, но её область видимости ограничена одним файлом**, в котором она определена. Из другого файла проекта к ней обратиться нельзя (см. [[08 Многофайловые проекты и библиотеки]]).

Важно и правило «видна только ниже объявления»:

```cpp
void func()
{
    stat_var = 10;          // ОШИБКА: stat_var объявлена ниже по тексту
}

static int stat_var = 100;

int main()
{
    stat_var = 5;           // здесь можно
    func();
}
```

### Переменные `static` внутри функции

Такая переменная **видна только внутри функции, но создаётся один раз и сохраняет значение между вызовами**:

```cpp
#include <iostream>

int counter()
{
    static int calls = 0;   // инициализация происходит один раз
    ++calls;
    return calls;
}

int main()
{
    for (int i = 0; i < 3; ++i)
        std::cout << counter() << ' ';
    std::cout << '\n';
}
// Вывод: 1 2 3
// Обычная int calls = 0; каждый раз давала бы 1 1 1
```

### Статические функции

`static` перед функцией ограничивает её видимость текущим файлом:

```cpp
static void helper() { /* ... */ }
```

> [!note] Две роли `static`
> У слова `static` две независимые роли: (1) **тип памяти**, статическая, с жизнью на всё время программы; (2) **ограничение области видимости** (для глобальных имён: одним файлом, для локальных: функцией).

## Автоматическая память

В автоматической памяти размещаются цепочка вызванных функций и обычные переменные, к которым мы привыкли, потому они и «автоматические». Она тоже выделяется ОС при старте и ограничена по размеру, но **время жизни автоматической переменной ограничено её областью видимости**: она создаётся при входе в блок и уничтожается при выходе из него.

```cpp
#include <iostream>

int main()
{
    for (int i = 0; i < 2; ++i)
    {
        int x = i * 10;                       // создаётся заново на каждой итерации
        std::cout << "x=" << x << " адрес " << &x << '\n';
    }   // x уничтожается здесь
}
```

Адрес `x` на разных итерациях может совпасть. Это нормально: когда переменная уничтожена, её место свободно, и умный компилятор переиспользует его. На другом компиляторе (например, Visual Studio в Windows) картина может быть иной: **как именно размещать переменные, решает компилятор**.

## Динамическая память

**Динамическая память — та, которой в программе управляет сам программист.** Он запрашивает у ОС столько, сколько нужно (теоретически ограничен объёмом оперативной памяти), а после использования обязан вернуть. Если забыть, возникает **утечка памяти (memory leak)**: программа потеряла доступ к блоку, а ОС считает его занятым, и никто другой его использовать не может. Подробно: [[08 Указатели и динамическая память]], позже [[02 Жизненный цикл объекта и RAII]].

## Пространства имён

**Конфликт имён** — ситуация, когда выбранное имя переменной или функции уже занято. В многофайловых проектах это частая беда: такие очевидные названия, как `sum` или `abs`, используются в разных контекстах.

**Пространство имён (namespace)** — область кода, в которой гарантируется уникальность идентификаторов. По умолчанию глобальные переменные и функции живут в **глобальном пространстве имён**. Свои пространства создаёт слово `namespace`:

```cpp
#include <iostream>

namespace my_namespace
{
    int value = 10;
}

namespace my_namespace      // то же пространство можно «открывать» повторно
{
    int number = 4;         // (в том числе в другом файле)
}

int main()
{
    my_namespace::value = 5;                       // :: — оператор разрешения области
    std::cout << my_namespace::value << ' '
              << my_namespace::number << '\n';     // 5 4
}
```

**Объявление пространства может быть разбросано по нескольким местам и файлам**, всё это одно пространство. Чтобы обратиться к имени из пространства, пишут `пространство::имя`.

Так же устроено `std::`: `std::cout`, `std::string` — имена стандартной библиотеки, вынесенные в пространство `std`, чтобы не конфликтовать с вашими.

### Решение конфликта имён

```cpp
#include <iostream>

int sum = 100;                     // глобальное пространство
namespace mylib { int sum = 5; }   // то же имя, но в своём пространстве

int main()
{
    std::cout << sum << ' '          // 100
              << mylib::sum << ' '   // 5
              << ::sum << '\n';      // 100: ::имя — явно из глобального
}
```

### `using namespace`

Конструкция `using namespace имя;` подключает пространство: после неё имена можно писать без префикса.

```cpp
namespace my_namespace { int value = 10; }

using namespace my_namespace;

int main()
{
    value = 5;     // value из my_namespace без префикса
}
```

> [!warning] Осторожно
> `using namespace` может вернуть конфликт имён (если `sum` есть и в глобальной области, и в подключённой, то `sum` станет неоднозначным, и компилятор выдаст ошибку). **Безопаснее всегда указывать пространство явно.** Особенно не стоит писать `using namespace std;` в заголовочных файлах.

### Вложенные пространства имён

Пространства можно вкладывать друг в друга для структурирования кода. Обращаться нужно по полному пути:

```cpp
#include <iostream>

namespace my_namespace
{
    namespace other_namespace
    {
        int value = 7;
    }
    int value = 10;
}

int main()
{
    std::cout << my_namespace::value << '\n';                     // 10
    std::cout << my_namespace::other_namespace::value << '\n';    // 7
}
// В этом коде используются три пространства: my_namespace, other_namespace и std
```

Длинный путь можно сократить псевдонимом: `namespace on = my_namespace::other_namespace;` и дальше `on::value` (в C++17 доступно и объявление `namespace a::b { ... }`).

## Частые ошибки
- Обратиться к `static`/глобальной переменной выше строки её объявления.
- Ожидать, что обычная локальная переменная «помнит» значение между вызовами (для этого нужен `static`).
- Писать `using namespace` для всего подряд и получать неоднозначные имена.
- Забыть освободить динамическую память.
- Считать, что адрес локальной переменной на разных итерациях цикла обязан меняться (или не меняться).

## Кратко (шпаргалка)

| Понятие | Суть |
|---|---|
| Статическая память | до `main`, живёт всю программу, фиксированный адрес |
| Автоматическая | локальные переменные, живут до конца блока |
| Динамическая | запрашивает и освобождает программист |
| `static` у глобального имени | видно только в этом файле |
| `static` у локальной переменной | одна на всю программу, значение сохраняется между вызовами |
| `namespace X { }` | своё пространство, доступ `X::имя` |
| `::имя` | имя из глобального пространства |
