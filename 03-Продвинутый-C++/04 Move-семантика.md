# Move-семантика

> [!abstract] О чём заметка
> Копирование больших объектов (массивов, строк, контейнеров) дорого, а во многих случаях копия не нужна: исходный объект всё равно скоро исчезнет. **Семантика перемещения** (move semantics) позволяет «забрать» ресурсы у такого объекта вместо копирования. Заметка объясняет `std::move`, lvalue и rvalue, правило пяти и оптимизации компилятора RVO/NRVO.

## Зачем нужно перемещение

**Семантика перемещения** — набор правил и средств языка C++, предназначенных для перемещения объектов, время жизни которых скоро истекает, вместо их копирования.

Рассмотрим функцию, меняющую местами два массива:

```cpp
void swap(std::vector<int>& lhs, std::vector<int>& rhs)
{
    std::vector<int> tmp = lhs;
    lhs = rhs;
    rhs = tmp;
}
```

Что с ней не так? Три присваивания — это три **глубоких копирования**: `std::vector` хранит элементы в куче, и копия выделяет новую память и переписывает все элементы. Для массивов по миллиону элементов получаем три миллиона лишних копирований, хотя нужно было лишь обменяться «владением» буферами.

Решение — `std::move`:

```cpp
void swap(std::vector<int>& lhs, std::vector<int>& rhs)
{
    std::vector<int> tmp = std::move(lhs);
    lhs = std::move(rhs);
    rhs = std::move(tmp);
}
```

Мы сообщаем компилятору, что эти объекты можно перемещать: `std::move` приводит их к специальной ссылке на rvalue. Вместо копирования элементов вектор просто забирает внутренний указатель на буфер, а у источника обнуляет.

```cpp
#include <iostream>
#include <utility>
#include <vector>

int main() {
    std::vector<int> a(1000000, 1), b(1000000, 2);
    const int* pa = a.data();
    const int* pb = b.data();

    std::vector<int> tmp = std::move(a);
    a = std::move(b);
    b = std::move(tmp);
    // буферы поменялись местами без единого копирования элемента
    std::cout << (a.data() == pb) << (b.data() == pa) << " " << a[0] << b[0] << "\n";
    // Вывод: 11 21

    std::vector<int> v(5, 7);
    std::vector<int> w = std::move(v);
    std::cout << v.size() << " " << w.size() << "\n";   // Вывод: 0 5
}
```

(Сам по себе обмен проще делать готовой функцией `std::swap`, внутри она устроена именно так.)

> [!warning] Что остаётся после перемещения
> Объект, из которого переместили, находится в **допустимом, но неопределённом состоянии** (valid but unspecified). Его можно уничтожить или присвоить ему новое значение, но не стоит рассчитывать на его содержимое. Для `std::vector` на практике он пуст, для умных указателей `unique_ptr` — равен `nullptr`.

## lvalue и rvalue

Чтобы понять `std::move`, нужно различать два вида выражений.

> [!note] lvalue и rvalue
> Если выражение ссылается на объект или у него можно взять адрес, это **lvalue** (имеет имя, «живёт» дальше этой строки). Всё остальное — **rvalue** (временные значения, результаты вычислений, которые скоро исчезнут).

```cpp
int a = 10;
a;                    // lvalue

int& b = a;
b;                    // lvalue, ссылается на a

void foo(int val) {
    val;              // lvalue: у параметра есть имя и адрес
}

int& bar() { return a; }
bar();                // lvalue (функция возвращает ссылку)

int baz() { return a; }
baz();                // rvalue (возвращается временное значение)
```

Для rvalue существует отдельный вид ссылки — **rvalue-ссылка** `T&&`. Она привязывается к временным значениям, и по ней можно безопасно «выкачать» ресурсы. Именно на этом различии устроена перегрузка: компилятор выбирает версию функции по виду выражения.

`std::move` **ничего не перемещает сам**: он лишь приводит lvalue к rvalue (`static_cast<T&&>`), разрешая вызвать версию, которая перемещает. Проверим:

```cpp
#include <iostream>
#include <utility>

int x = 0;
int val() { return 0; }
int& ref() { return x; }

void test(int&)  { std::cout << "lvalue\n"; }
void test(int&&) { std::cout << "rvalue\n"; }

int main() {
    test(0);             // rvalue: литерал
    test(x);             // lvalue: переменная
    test(val());         // rvalue: результат функции по значению
    test(ref());         // lvalue: функция вернула ссылку
    test(std::move(x));  // rvalue: lvalue приведён к rvalue
}
// Вывод: rvalue lvalue rvalue lvalue rvalue (каждое с новой строки)
```

Подробнее о ссылках — в [[07 Указатели и массивы]] и [[05 Функции и рекурсия]].

### Когда перемещение не помогает

- Если основные данные объекта лежат **на стеке** (например, `int`, `double`, `std::array<int, 1000>`), то перемещать нечего: данные всё равно придётся скопировать. Выигрыш бывает у объектов, которые владеют ресурсом в куче (вектор, строка, указатель на буфер, файл).
- `std::move` для **константного** объекта бесполезен: из `const`-объекта нельзя ничего забрать, поэтому выбирается копирование.

```cpp
const std::string cs = "const";
std::string s2 = std::move(cs);   // молча выполнится копирование
```

## Правило пяти

Для классов, владеющих ресурсом, действует **правило пяти** (rule of five): если классу нужна собственная реализация одного из пяти специальных методов, то скорее всего ему нужны все пять:

| Метод | Сигнатура | Когда вызывается |
|---|---|---|
| деструктор | `~T()` | объект уничтожается |
| конструктор копирования | `T(const T&)` | `T b = a;` (lvalue) |
| копирующее присваивание | `T& operator=(const T&)` | `b = a;` |
| конструктор перемещения | `T(T&&) noexcept` | `T b = std::move(a);` или из временного |
| перемещающее присваивание | `T& operator=(T&&) noexcept` | `b = std::move(a);` |

Логика такая: если нужен деструктор, значит, класс владеет ресурсом (память, файл), а значит, сгенерированное по умолчанию копирование (простое побайтовое) приведёт к двойному освобождению — копирование нужно определить. А раз определено копирование, неявного перемещения не будет, и класс станет «дорогим» — поэтому добавляют перемещение. Ещё лучше — вообще не владеть ресурсом напрямую, а использовать `std::vector`, `std::string` и умные указатели: тогда все пять методов генерируются правильно сами (**правило нуля**, rule of zero). См. [[03 Умные указатели]] и [[02 Жизненный цикл объекта и RAII]].

Пример из лекции — класс-обёртка над C-строкой (я добавил метод `c_str` и вывод в методах, чтобы увидеть, какой из них вызывается):

```cpp
#include <cstring>
#include <iostream>
#include <utility>

class rule_of_five {
    char* cstring;                                   // сырой указатель
public:
    rule_of_five(const char* s = "") : cstring(nullptr) {
        if (s) {
            std::size_t n = std::strlen(s) + 1;
            cstring = new char[n];
            std::memcpy(cstring, s, n);
        }
    }
    ~rule_of_five() { delete[] cstring; }            // деструктор

    rule_of_five(const rule_of_five& other)          // конструктор копирования
        : rule_of_five(other.cstring) { std::cout << "copy ctor\n"; }

    rule_of_five(rule_of_five&& other) noexcept      // конструктор перемещения
        : cstring(std::exchange(other.cstring, nullptr)) { std::cout << "move ctor\n"; }

    rule_of_five& operator=(const rule_of_five& other) {   // копирующее присваивание
        std::cout << "copy assign\n";
        return *this = rule_of_five(other);          // копия во временный объект + перемещение
    }

    rule_of_five& operator=(rule_of_five&& other) noexcept {   // перемещающее присваивание
        std::cout << "move assign\n";
        std::swap(cstring, other.cstring);
        return *this;
    }

    const char* c_str() const { return cstring ? cstring : "(null)"; }
};

int main() {
    rule_of_five a("hello");
    rule_of_five b = a;               // копия
    rule_of_five c = std::move(a);    // перемещение: a опустошён
    std::cout << "a=" << a.c_str() << " b=" << b.c_str() << " c=" << c.c_str() << "\n";
    b = c;                            // копирующее присваивание
    b = rule_of_five("temp");         // перемещающее присваивание из временного объекта
    std::cout << b.c_str() << "\n";
}
// Вывод:
// copy ctor
// move ctor
// a=(null) b=hello c=hello
// copy assign
// copy ctor
// move assign
// move assign
// temp
```

Разберём приёмы.

- **Конструктор перемещения** принимает `rule_of_five&&` и забирает указатель: `std::exchange(other.cstring, nullptr)` возвращает старое значение и записывает `nullptr` в источник. Теперь деструктор источника сделает `delete[] nullptr` — безопасно, а буфер остался только у нового объекта.
- **Перемещающее присваивание** обменивает указатели (`std::swap`): старые данные получателя уйдут вместе с временным объектом, который скоро уничтожится.
- **Копирующее присваивание** реализовано «через копию и перемещение»: делается копия `rule_of_five(other)` и перемещается в `*this`. Это же работает и при самоприсваивании `a = a`.
- Перемещающие операции помечают `noexcept`: они ничего не выделяют и не бросают исключений. Это важно, потому что `std::vector` при перевыделении памяти использует перемещение элементов **только если оно `noexcept`**, иначе копирует (для сохранения строгой гарантии безопасности исключений).

### Запрет копирования

Операции можно запрещать явно через `= delete`:

```cpp
rule_of_five& operator=(const rule_of_five& other) = delete;
```

(В слайдах такая запись описана как запрет «обычного перемещения», но на самом деле она запрещает **копирование**.) Если запретить копирование и оставить перемещение, получится **перемещаемый, но не копируемый** тип: как `std::unique_ptr` или `std::fstream`.

```cpp
#include <iostream>
#include <memory>

struct Buf {
    Buf() = default;
    Buf(const Buf&) = delete;                // копировать нельзя
    Buf& operator=(const Buf&) = delete;
    Buf(Buf&&) = default;                    // перемещать можно
    Buf& operator=(Buf&&) = default;
    std::unique_ptr<int> p = std::make_unique<int>(1);
};

Buf make() { return Buf(); }

int main() {
    Buf a = make();
    Buf b = std::move(a);
    // Buf c = b;   // ошибка компиляции: копирующий конструктор удалён
    std::cout << (a.p == nullptr) << (b.p != nullptr) << "\n";   // Вывод: 11
}
```

## RVO и NRVO

Возврат объекта из функции по значению выглядит дорогим: вроде бы нужно создать локальный объект, скопировать его в результат и уничтожить локальный.

**NRVO** (Named Return Value Optimization) — оптимизация, при которой компилятор в некоторых случаях **может** (но это не гарантировано) вместо копирования или перемещения создать результат сразу в том месте, где его ждёт вызывающий код.

```cpp
my_class func() {
    my_class local_variable;
    // действия с local_variable
    return local_variable;
}

my_class result = func();
```

«По букве» должно быть так: конструктор по умолчанию для `local_variable`, копирование в `result`, деструктор `local_variable`. Но компилятор с NRVO создаёт `result` прямо в месте вызова, так что копирования и лишнего деструктора нет.

**Условия** для применения NRVO:

- возвращается именно локальный объект, а не ссылка или часть объекта;
- тип возвращаемого значения из сигнатуры совпадает с типом локального объекта.

**RVO** — то же самое для безымянных временных объектов: `my_class f() { return my_class(); }`. Здесь оптимизация проще; в C++17 она для таких случаев (prvalue) **обязательна** по стандарту. Убедимся:

```cpp
#include <iostream>

struct my_class {
    my_class()                 { std::cout << "ctor\n"; }
    my_class(const my_class&)  { std::cout << "copy\n"; }
    my_class(my_class&&) noexcept { std::cout << "move\n"; }
    ~my_class()                { std::cout << "dtor\n"; }
};

my_class func() { my_class local_variable; return local_variable; }   // NRVO
my_class f()    { return my_class(); }                                // RVO

int main() {
    std::cout << "-- NRVO\n";
    my_class result = func();
    std::cout << "-- RVO\n";
    my_class r2 = f();
    std::cout << "-- конец\n";
}
// Вывод (g++ -std=c++17):
// -- NRVO
// ctor
// -- RVO
// ctor
// -- конец
// dtor
// dtor
```

Ни `copy`, ни `move` не вызваны. Если отключить оптимизацию флагом `-fno-elide-constructors`, то для NRVO появятся лишние `move` и `dtor` (RVO по-прежнему останется, потому что он гарантирован в C++17).

> [!warning] Не пишите `return std::move(local);`
> `std::move` на возвращаемой локальной переменной **мешает** NRVO: тип выражения меняется, и компилятор не может исключить копирование. g++ с `-Wall` предупреждает: `moving a local object in a return statement prevents copy elision`. Пишите просто `return local;` — если оптимизация не сработает, компилятор сам попробует перемещение.

## Частые ошибки

- Использовать объект после `std::move` (его состояние не определено: допустимы только уничтожение и присваивание нового значения).
- Применять `std::move` к `const`-объекту: получится незаметное копирование.
- Писать `return std::move(local);` — отключает NRVO.
- Забыть `noexcept` у перемещающих операций: контейнеры тогда предпочтут копирование (`std::vector<U>` с перемещением без `noexcept` при росте копирует элементы).
- Реализовать деструктор, но не определить копирование: две копии удалят один и тот же буфер.
- Ожидать, что `std::move` сам что-то перемещает. Это только приведение типа.

## Задачи для практики

1. Объясните, почему `std::vector<int> a = std::move(b);` работает за $O(1)$, а `std::vector<int> a = b;` — за $O(n)$. Решение: вектор хранит указатель на буфер в куче; перемещение копирует только этот указатель (и размер), а копирование — все $n$ элементов.
2. Что выведет `test(std::move(x))` для `void test(int&); void test(int&&);`? Решение: `rvalue`.
3. Реализуйте для своего класса `Buffer` с полем `int* data; size_t size;` все пять методов. Решение: по образцу `rule_of_five`: деструктор `delete[] data`; копирование выделяет новый массив и копирует `size` элементов; перемещение забирает `data` и `size`, обнуляя источник (`std::exchange`), и помечается `noexcept`.

## Кратко (шпаргалка)

- Перемещение забирает ресурсы у объекта, которому они больше не нужны, вместо копирования.
- `std::move(x)` = приведение к rvalue; сам по себе ничего не перемещает.
- lvalue: есть имя и адрес; rvalue: временное значение. Для `T&&` выбирается перемещающая версия.
- После перемещения объект допустим, но не определён: используйте только присваивание и уничтожение.
- Правило пяти: деструктор, копирующий и перемещающий конструкторы, копирующее и перемещающее присваивания. Лучше — правило нуля (стандартные контейнеры и умные указатели).
- Перемещающие операции — `noexcept`.
- RVO/NRVO: возврат локального объекта по значению дёшев; не пишите `return std::move(local);`.
