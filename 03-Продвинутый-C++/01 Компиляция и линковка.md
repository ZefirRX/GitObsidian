# Компиляция и линковка

> [!abstract] О чём заметка
> Исходный `.cpp`-файл — это просто текст, процессор выполнить его не может. Заметка разбирает, через какие четыре этапа текст превращается в программу (препроцессинг, компиляция, ассемблирование, линковка), какие ошибки возникают на каждом из них и как по сообщению понять, на какой стадии что сломалось.

## Зачем вообще компилировать

Процессор понимает только **машинный код (machine code)** — последовательности двоичных инструкций. Чтобы он «понял», что мы от него хотим, программу нужно перевести на его язык. Результатом сборки исходных файлов бывает один из артефактов:

- исполняемый файл;
- динамическая библиотека (`.so`, `.dll`);
- статическая библиотека (`.a`, `.lib`).

Команда `g++ main.cpp -o main` выглядит как одно действие, но внутри работает конвейер из четырёх стадий.

```mermaid
flowchart LR
    A["main.cpp<br/>исходный текст"] -->|препроцессор| B["main.ii<br/>развёрнутый C++"]
    B -->|компилятор| C["main.s<br/>ассемблер"]
    C -->|ассемблер| D["main.o<br/>объектный файл"]
    D -->|линкер + другие .o и библиотеки| E["main<br/>исполняемый файл"]
```

Каждую стадию можно остановить и посмотреть результат — это удобно и для обучения, и для отладки:

```bash
g++ -std=c++17 -E main.cpp -o main.ii   # только препроцессинг
g++ -std=c++17 -S main.cpp -o main.s    # до ассемблерного кода
g++ -std=c++17 -c main.cpp -o main.o    # до объектного файла
g++ main.o -o main                      # линковка
```

Единица компиляции — один `.cpp`-файл вместе со всеми подставленными в него заголовками (**единица трансляции**, translation unit). Компилятор видит только её и ничего не знает о других `.cpp` проекта: связать их воедино — работа линкера.

## 1. Препроцессинг

**Препроцессинг** (preprocessing) — обработка исходных файлов специальной утилитой, текстовым препроцессором. Он ничего не «понимает» в C++, а лишь правит текст:

- вставляет содержимое заголовочных файлов вместо `#include`;
- выполняет макроподстановки (`#define`);
- обрабатывает директивы условной компиляции (`#if`, `#ifdef`, …);
- заменяет комментарии пустыми строками.

На выходе получается огромный файл, состоящий исключительно из конструкций C++ (расширение обычно `.i` или `.ii`). Сами директивы подробно разобраны в [[07 Препроцессор и макросы]].

Возьмём короткую программу:

```cpp
#include <iostream>
#define N 3
int main() {
    // комментарий
    std::cout << N * 2 << "\n";
    return 0;
}
```

После `g++ -E` файл разрастается примерно до 36 тысяч строк (в основном это содержимое `<iostream>` и всего, что оно подключает; точное число зависит от версии компилятора), а в самом конце остаётся:

```cpp
int main() {

    std::cout << 3 * 2 << "\n";
    return 0;
}
```

`N` заменено на `3`, комментарий превратился в пустую строку. Строки вида `# 1 "Source.cpp"` в начале и посреди файла — служебные пометки о том, из какого файла и какой строки пришёл фрагмент; по ним компилятор потом показывает правильные номера строк в сообщениях об ошибках.

> [!tip] Зачем смотреть на `.ii`
> Если макрос или `#include` ведёт себя странно, посмотрите вывод `g++ -E`: вы увидите ровно тот код, который получит компилятор.

## 2. Компиляция

**Компиляция** — преобразование кода после препроцессинга в код на машинном языке (бинарный) или на языке, близком к машинному и доступном для чтения человеком (чаще всего это ассемблер). Это промежуточный шаг между высокоуровневым C++ и машинным кодом. Она состоит из нескольких фаз; в разных компиляторах они могут выполняться раздельно или быть совмещены:

1. лексический анализ;
2. синтаксический анализ;
3. оптимизация;
4. генерация кода.

### Лексический анализ

Последовательность символов превращается в последовательность **лексем** (токенов) — минимальных осмысленных единиц: ключевых слов, имён, операторов, скобок. Строка

```cpp
int val = (value1 - value2);
```

превращается примерно в такой поток: ключевое слово `int`, ИМЯ `val`, ПРИСВАИВАНИЕ, ОТКРЫВАЮЩАЯ_СКОБКА, ИМЯ `value1`, МИНУС, ИМЯ `value2`, ЗАКРЫВАЮЩАЯ_СКОБКА, ТОЧКА_С_ЗАПЯТОЙ.

### Синтаксический анализ

Поток лексем собирается в **дерево разбора** (parse tree), которое отражает структуру выражения и приоритет операций. Для `1 + 2 * 3` дерево такое:

```text
        +
       / \
      1   *
         / \
        2   3
```

Умножение оказывается глубже сложения, значит, вычисляется первым. Здесь же проверяется, что лексемы вообще складываются в допустимую грамматикой конструкцию — отсюда «синтаксические» ошибки.

### Оптимизация

Компилятор удаляет излишние конструкции и упрощает код, не меняя его наблюдаемого поведения.

| Уровень | Примеры |
|---|---|
| Высокоуровневая | удаление мёртвого кода и ненужных присваиваний, оптимизация циклов, оптимизация множественных ветвлений |
| Низкоуровневая | оптимальный выбор инструкций, векторизация (одна инструкция обрабатывает сразу блок данных), изменение порядка инструкций |

Включается флагами `-O1`, `-O2`, `-O3`. Эффект хорошо виден на `int x = 1 + 2 * 3; return x;`: при `-O0` (без оптимизаций) компилятор честно кладёт 7 на стек и читает обратно, а при `-O2` сразу пишет `movl $7, %eax` — значение посчитано на этапе компиляции, переменной в памяти нет вовсе.

### Генерация кода

Из промежуточного представления создаётся код на языке, близком к машинному (ассемблер, файл `.s`).

## 3. Ассемблирование

Процессоры исполняют машинный код, поэтому ассемблерный код нужно перевести в машинный. Этот процесс и называется **ассемблированием**. **Ассемблер** сохраняет результат в **объектном файле** (`.o` или `.obj`) — бинарном файле с набором функций и данных. Но это ещё не завершающий этап: объектных файлов может быть много, и их нужно собрать в один исполняемый. Пока же в объектном файле вместо адресов функций из других файлов остаются «пустые места».

Посмотреть, что объектный файл определяет сам (`T`, text), а чего ждёт извне (`U`, undefined), можно утилитой `nm`:

```bash
nm -C main.o | grep -E ' (T|U) '
#                  U std::cout                        <- нужен снаружи (из библиотеки)
#                  U std::ostream::operator<<(int)    <- тоже снаружи (и ещё несколько U-символов)
# 0000000000000000 T main                             <- определён здесь
```

Без флага `-C` имена выглядят как `_Z1fv`: в C++ из-за перегрузки функций компилятор **искажает имена** (name mangling), зашивая в них типы параметров (`f()` → `_Z1fv`). Флаг `-C` возвращает читаемый вид.

## 4. Линковка

**Линковка** (linking, компоновка) — объединение всех объектных файлов и статических библиотек в единый исполняемый файл. Её главная задача — **подставить адреса вызовов внешних объектов**, которые образовались в объектных файлах проекта. Если `main.o` вызывает функцию `f` из `util.o`, линкер находит её адрес и вписывает в вызов.

Для этого используется **таблица символов** — структура, созданная компилятором. Она хранит имена переменных, функций и классов, а каждому идентификатору (символу) сопоставляет тип, область видимости и адреса ссылок на данные и функции в других объектных файлах.

> [!note] Объявление и определение
> **Объявление** (declaration) сообщает компилятору «такая функция существует» (`void func(int);`). **Определение** (definition) задаёт её тело. Для компиляции вызова достаточно объявления, а линкеру нужно ровно одно определение. На этом различии построены многофайловые проекты — см. [[08 Многофайловые проекты и библиотеки]].

Полный цикл на двух файлах:

```cpp
// util.h
int twice(int x);

// util.cpp
int twice(int x) { return 2 * x; }

// main.cpp
#include <iostream>
#include "util.h"
int main() { std::cout << twice(21) << "\n"; }
```

```bash
g++ -std=c++17 -Wall -c util.cpp main.cpp   # два объектных файла
g++ main.o util.o -o app                    # линковка
./app                                       # Вывод: 42
```

Компиляция `main.cpp` проходит, потому что объявление `twice` есть в заголовке; адрес функции вписывает линкер, когда видит `util.o`. Вместо объектного файла можно подключить библиотеку: статическую (`ar rcs libutil.a util.o`, затем `g++ main.o -L. -lutil`) — её код копируется в исполняемый файл, либо динамическую (`g++ -shared -fPIC util.cpp -o libutil.so`) — она подгружается при запуске. Подробности — в [[09 Сборка и подключение библиотек]], а автоматизация всего процесса — в [[10 CMake]].

## Ошибки: на какой стадии что ломается

| Тип ошибки | Когда обнаруживается | Типичные причины |
|---|---|---|
| Синтаксическая | компиляция | пропущена `;` или скобка, необъявленная переменная, неверная конструкция |
| Семантическая | компиляция | синтаксис верен, но нарушены правила языка на уровне смысла |
| Логическая | выполнение (компилятор не видит) | код делает не то, что задумано |
| Ошибка линковки | линковка | нет `main`, функция не определена или определена дважды |

### Синтаксические ошибки

Нарушены правила языка. Самые частые: пропущена скобка, пропущена точка с запятой, обращение к необъявленной переменной. Исправлять их легко — достаточно прочитать сообщение компилятора. Пример из занятия:

```cpp
#include <iostream>
int main()
{
    int x = 10;
    std::cout << " " << x   // пропущена точка с запятой
    return 0;
}
```

```text
error: expected ';' before 'return'
```

Другой пример — цикл `while(!){ x++; }`: у оператора `!` нет операнда, то есть условие цикла некорректно.

### Семантические и логические ошибки

Код допустим по грамматике, но нарушает правила языка по смыслу или делает не то, что нужно. Такие ошибки сложнее отловить.

```cpp
int main() {
    int a = 4, b = 1, c = 4;
    a + b = c;     // нельзя присваивать результату выражения
}
```

g++ сообщает `error: lvalue required as left operand of assignment`: слева от `=` должно стоять то, чему можно присвоить значение (подробнее про lvalue и rvalue — в [[04 Move-семантика]]).

Самые коварные ошибки компилятор не поймает вообще:

```cpp
#include <iostream>
int sum(int x, int y) {
    return x - y;     // название говорит «сумма», а считаем разность
}
int main() {
    std::cout << sum(5, 3);   // Вывод: 2, а ожидали 8
}
```

И ещё одна: если в `main` сначала стоит `return 0;`, а вывод идёт после него, то на экран ничего не попадёт — код после `return` недостижим. Заметим, что g++ даже с `-Wall -Wextra` об этом не предупреждает. Такие ошибки ловят тестами — см. [[08 Тестирование и Unit-тесты]].

### Ошибки линковки

Возникают уже после успешной компиляции. Три классических случая.

**1. Функция объявлена, но не определена.** В слайдах это сформулировано как «нет реализации `func`; есть только объявление»:

```cpp
#include <string>
void func(std::string str);                // только объявление
int main() { func("tmp"); }                // вызов есть, тела нет
```

```text
undefined reference to `func(std::__cxx11::basic_string<...>)'
collect2: error: ld returned 1 exit status
```

**2. Нет функции `main`.** Опечатка `int ain()` — компиляция проходит, а линкер, собирая программу, не находит точку входа:

```text
(.text+0x1b): undefined reference to `main'
```

**3. Определение дублируется.** Одна и та же функция определена в двух единицах трансляции, которые собираются вместе:

```text
multiple definition of `f()'; b.o:b.cpp:(.text+0x0): first defined here
```

> [!warning] Как отличить ошибку компиляции от ошибки линковки
> Сообщения линкера начинаются с `/usr/bin/ld:` или содержат `undefined reference` / `multiple definition` / `ld returned 1 exit status`. Это сигнал: исходный текст грамматически в порядке, а не хватает или дублируется *определение*. Править нужно набор файлов в сборке или сами определения, а не скобки и точки с запятой.

## Частые ошибки

- Путать «функция объявлена» и «функция определена»: заголовок включён, а `.cpp` с реализацией не добавлен в сборку.
- Определять обычную (не `inline`) функцию прямо в заголовке, подключаемом из нескольких `.cpp`: получится `multiple definition of 'twice(int)'`.
- Искать причину `undefined reference` в синтаксисе: правкой скобок она не лечится.
- Забывать подключить библиотеку при линковке (`-lname`): компиляция пройдёт, а на линковке будут `undefined reference`.

## Задачи для практики

Найдите ошибку и скажите, на какой стадии она проявится.

1. `std::cout << " " << x` без `;` перед `return` — синтаксическая, компиляция.
2. `while(!){ x++; }` — синтаксическая, компиляция.
3. `a + b = c;` — семантическая, компиляция (`lvalue required`).
4. `int sum(int x, int y) { return x - y; }` — логическая, не обнаруживается автоматически.
5. `return 0;` перед `std::cout << ...` — логическая, вывода не будет.
6. Функция объявлена без определения и вызвана — линковка (`undefined reference`).
7. `int ain()` вместо `main` — линковка (нет точки входа).

## Кратко (шпаргалка)

| Этап | Вход → выход | Что делает | Флаг g++ |
|---|---|---|---|
| Препроцессинг | `.cpp` → `.ii` | `#include`, `#define`, `#if`, убирает комментарии | `-E` |
| Компиляция | `.ii` → `.s` | лексика, синтаксис, оптимизация, генерация кода | `-S` |
| Ассемблирование | `.s` → `.o` | ассемблер → машинный код | `-c` |
| Линковка | `.o` + библиотеки → exe | подставляет адреса внешних символов | (без флага) |

- Объявление нужно компилятору, определение — линкеру.
- `nm -C file.o`: `T` — определено здесь, `U` — ждёт линкера.
