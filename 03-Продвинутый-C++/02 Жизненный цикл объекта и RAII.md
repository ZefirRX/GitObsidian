# Жизненный цикл объекта и RAII

> [!abstract] О чём заметка
> Любой объект создаётся, живёт и уничтожается, и от того, где он лежит (стек или куча), зависит, кто отвечает за его уничтожение. **RAII** — главная идиома C++, которая перекладывает эту ответственность на деструкторы и делает код безопасным даже при исключениях. На ней построены умные указатели, `std::fstream`, `std::lock_guard` и многое другое.

## Три стадии жизни объекта

Любой объект в программе проходит три стадии.

| Стадия | Что происходит |
|---|---|
| 1. Создание | выделяется память под объект, вызывается конструктор |
| 2. Жизнь | над объектом выполняются какие-то действия |
| 3. Удаление | вызывается деструктор, освобождаются ресурсы, выделенные под объект |

Память под объект выделяется двумя способами: **на стеке** или **в куче**.

| | Стек (stack) | Куча (heap) |
|---|---|---|
| Устройство | память по принципу LIFO (last in, first out): последний добавленный кусок первым снимается | «склад» переменных; работа через указатели |
| Плюсы | быстро; освобождается автоматически | можно выделять динамически, ограничение — только физический объём памяти |
| Минусы | фиксированный размер, при переполнении — аварийное завершение | «плата за гибкость»: медленнее; возможны утечки памяти |

Подробнее об устройстве этих областей — в [[09 Модель памяти]] и [[08 Указатели и динамическая память]].

## Объекты на стеке: автоматические переменные

**Блок кода** — фрагмент программы, ограниченный фигурными скобками. Переменная, объявленная внутри блока, помещается в стековую память и «живёт» до конца блока. Как только мы выходим из блока, для неё вызывается деструктор, который освобождает занятые ресурсы. Такие переменные называют **автоматическими** (automatic).

Важное правило: **объекты уничтожаются в порядке, обратном порядку создания** — так устроен стек.

```cpp
#include <iostream>
#include <string>

struct Noisy {
    std::string name;
    explicit Noisy(std::string n) : name(std::move(n)) { std::cout << "создан " << name << "\n"; }
    ~Noisy() { std::cout << "уничтожен " << name << "\n"; }
};

void some_function() {
    Noisy s("s");
    Noisy class1("class1");
    Noisy class2("class2");
    std::cout << "работаем\n";
}   // здесь все три объекта уничтожаются

int main() {
    some_function();
}
// Вывод:
// создан s
// создан class1
// создан class2
// работаем
// уничтожен class2
// уничтожен class1
// уничтожен s
```

Название «стек» понятно из схемы состояния памяти: объекты кладутся друг на друга, а при выходе из блока снимаются сверху вниз.

```text
вход в блок:    s  ->  s, class1  ->  s, class1, class2
выход из блока: s, class1, class2  ->  s, class1  ->  s  ->  (пусто)
```

### Исключения не мешают

Деструкторы срабатывают **при любом выходе из блока**: по концу блока, через `return` или при исключении. Во время исключения происходит **раскрутка стека** (stack unwinding): все уже созданные автоматические объекты уничтожаются в обратном порядке, пока исключение не найдёт подходящий `catch` (подробнее — в [[06 Исключения и обработка ошибок]]).

```cpp
#include <iostream>
#include <stdexcept>
#include <string>

struct Noisy {
    std::string name;
    explicit Noisy(std::string n) : name(std::move(n)) { std::cout << "создан " << name << "\n"; }
    ~Noisy() { std::cout << "уничтожен " << name << "\n"; }
};

void with_exception() {
    Noisy a("a");
    Noisy b("b");
    throw std::runtime_error("ой");
}

int main() {
    try {
        with_exception();
    } catch (const std::exception& e) {
        std::cout << "поймали: " << e.what() << "\n";
    }
}
// Вывод:
// создан a
// создан b
// уничтожен b
// уничтожен a
// поймали: ой
```

Обратите внимание: `a` и `b` уничтожены *до* входа в `catch`.

## Объекты в куче: ручное управление

Время жизни объектов, созданных в динамической памяти, контролирует программист: создаются они через `new`, удаляются через `delete` (для массивов — `delete[]`). Именно здесь возникают **утечки памяти** (memory leak) — выделенная память не возвращается системе, пока работает программа.

Самый простой случай — забыли `delete[]`:

```cpp
void some_func() {
    int* arr = new int[10];
    // ... какой-то код ...
}   // delete[] нет: 40 байт утекли
```

Менее очевидный случай — исключение:

```cpp
void some_func() {
    int* arr = new int[10];
    func();            // если здесь вылетит исключение...
    delete[] arr;      // ...эта строка не выполнится: утечка
}
```

Если `func` (или любое место до `delete[]`) бросит исключение, блок будет покинут аварийно, и вызов `delete[]` не произойдёт. То же с несколькими `return`: пришлось бы дублировать `delete[]` перед каждым. Нужна конструкция, которая освобождает ресурс сама, — и это RAII.

## Идиома RAII

> [!note] RAII
> **RAII** (Resource Acquisition Is Initialization, «получение ресурса есть инициализация») — идиома, по которой с каждым фактом захвата ресурса связывается переменная на стеке (автоматическая переменная). Эта переменная возвращает ресурс, когда он больше не нужен, с помощью своего деструктора.

**Ресурс** — всё, что программа «берёт напрокат» у операционной системы: память, файл, сокет, мьютекс, соединение с базой данных. Схема всегда одна:

| Момент | Действие |
|---|---|
| конструктор | захватываем ресурс (если не получилось — бросаем исключение) |
| время жизни | пользуемся ресурсом через методы класса |
| деструктор | освобождаем ресурс |

Так как деструктор автоматической переменной гарантированно вызывается при выходе из блока (в том числе из-за исключения), ресурс гарантированно вернётся.

### Пример 1: тот же массив, но через RAII-обёртку

```cpp
#include <iostream>
#include <stdexcept>

void func() { throw std::runtime_error("fail"); }

class ArrayGuard {
    int* p;
public:
    explicit ArrayGuard(std::size_t n) : p(new int[n]) {}
    ~ArrayGuard() { delete[] p; std::cout << "память освобождена\n"; }
    int* get() { return p; }
    ArrayGuard(const ArrayGuard&) = delete;
    ArrayGuard& operator=(const ArrayGuard&) = delete;
};

void safe() {
    ArrayGuard arr(10);
    arr.get()[0] = 1;
    func();                 // исключение
}

int main() {
    try { safe(); } catch (const std::exception& e) { std::cout << e.what() << "\n"; }
}
// Вывод:
// память освобождена
// fail
```

В варианте с голым `new` та же программа, запущенная под `-fsanitize=address`, сообщает: `Direct leak of 40 byte(s)`. С обёрткой утечки нет, и `delete[]` писать не нужно. В реальном коде такую обёртку не пишут руками, а берут `std::vector` или умный указатель — см. [[03 Умные указатели]].

### Пример 2: файл

Код в стиле C:

```cpp
FILE* f = fopen("out.txt", "w");
if (f != nullptr) {
    fprintf(f, "hello world!\n");
    // ... какой-то код (а вдруг тут исключение или return?) ...
    fclose(f);          // закрывать приходится вручную
} else {
    printf("file open failed\n");
}
```

Проблема: `fclose` нужно не забыть вызвать на каждом пути выхода, то есть всё освобождать нужно вручную.

Тот же файл через RAII-обёртку. Это исправленная версия класса из лекции: вместо `fprintf(f, str.c_str())` (строка с данными используется как формат, и символ `%` в ней приведёт к неопределённому поведению) применён `fputs`; копирование запрещено (две копии закрыли бы один и тот же `FILE*` дважды).

```cpp
#include <cstdio>
#include <iostream>
#include <stdexcept>
#include <string>

class file {
    FILE* f;
public:
    explicit file(const std::string& filename) {
        f = std::fopen(filename.c_str(), "w");
        if (f == nullptr) {
            throw std::runtime_error("file open failed");   // объект не создан -> деструктор не вызовется
        }
    }
    void write(const std::string& str) { std::fputs(str.c_str(), f); }
    ~file() { std::fclose(f); std::cout << "файл закрыт\n"; }

    file(const file&) = delete;                // копировать нельзя
    file& operator=(const file&) = delete;
};

int main() {
    try {
        file f("out.txt");
        f.write("hello world\n");
        throw std::runtime_error("что-то пошло не так");   // файл всё равно закроется
    } catch (const std::exception& e) {
        std::cout << "ошибка: " << e.what() << "\n";
    }
    try {
        file g("/nonexistent/dir/out.txt");                // конструктор бросит исключение
    } catch (const std::exception& e) {
        std::cout << "ошибка: " << e.what() << "\n";
    }
}
// Вывод:
// файл закрыт
// ошибка: что-то пошло не так
// ошибка: file open failed
```

В слайдах RAII реализована именно такой простой «оберткой»: классом, который управляет записью в файл. Теперь файл закрывать вручную не нужно — при уничтожении объекта `file` вызовется деструктор и выполнит необходимую работу за нас.

> [!warning] Если конструктор бросил исключение
> Объект считается несозданным, и его деструктор **не вызывается**. Поэтому конструктор должен захватывать ресурс так, чтобы при неудаче нечего было освобождать (как здесь: `fopen` не удался — закрывать нечего). Если же в конструкторе захватывается несколько ресурсов, каждый из них должен быть в своём RAII-члене.

### Что в стандартной библиотеке уже сделано по RAII

| Класс | Какой ресурс он держит |
|---|---|
| `std::unique_ptr`, `std::shared_ptr` | память в куче — [[03 Умные указатели]] |
| `std::vector`, `std::string` | динамический массив символов/элементов |
| `std::fstream` | файловый дескриптор — [[11 Работа с файлами]] |
| `std::lock_guard` | захваченный мьютекс |

Пример с мьютексом: как бы мы ни вышли из функции, мьютекс будет отпущен.

```cpp
#include <iostream>
#include <mutex>

std::mutex m;
int counter = 0;

void inc() {
    std::lock_guard<std::mutex> lock(m);   // захват в конструкторе
    ++counter;
    if (counter > 0) return;               // ранний выход: деструктор всё равно отпустит мьютекс
}

int main() {
    inc();
    inc();
    std::cout << counter << "\n";   // Вывод: 2
}
```

> [!tip] Практическое правило
> Не пишите «голые» `new`/`delete` в прикладном коде. Если нужно владеть ресурсом, оберните его в класс с деструктором или возьмите готовый. Когда в классе появляется деструктор, освобождающий ресурс, позаботьтесь и о копировании и перемещении — см. «правило пяти» в [[04 Move-семантика]].

## Частые ошибки

- Выделить память через `new` и выйти раньше `delete` (ранний `return`, исключение).
- Сделать RAII-класс копируемым без продуманной семантики: две копии освободят один ресурс дважды.
- Захватывать ресурс не в конструкторе, а в отдельном методе `open()`: появляется «полуготовое» состояние объекта, и идиома теряет смысл.
- Бросать исключения из деструктора (во время раскрутки стека это приводит к `std::terminate`).

## Кратко (шпаргалка)

- Жизнь объекта: создание → использование → удаление.
- Стек: быстро, автоматически, порядок уничтожения обратный созданию. Куча: гибко, но освобождать нужно вручную.
- RAII: ресурс = автоматическая переменная; захват в конструкторе, освобождение в деструкторе.
- Деструктор срабатывает при любом выходе из блока, в том числе при исключении.
- Ресурсы — не только память: файлы, мьютексы, сокеты.
